API reference

This page and SciML problems and functions list the functions and types of CasADiCodegen.jl, grouped by task. The package exports build_function, generate_julia, CasadiFunction, casadi_function and casadi. The other names below are public and need the prefix CasADiCodegen.. The exceptions are callback, integrator and rootfinder: they are front-end functions to which the package adds methods.

Differences from CasADi's Python API

using CasADiCodegen loads CasADiNative.jl, the Julia front end of CasADi 3.8.2. Its calls follow the CasADi documentation for Python, with these differences:

  • SX, MX, DM, jacobian, gradient, hessian, substitute, nlpsol, integrator, rootfinder, callback and the Opti functions Opti, variable, parameter, minimize, subject_to, bounded, set_initial, solve and value are exported. Every other function is in the exported module casadi, as in Python: casadi.set_value, casadi.sumsqr.
  • CasadiFunction makes a CasADi function, since Function is a Julia type; the type of the result is CasADiCodegen.Function.
  • Operations have their Julia meaning: * is the matrix product, sin.(x) and x .^ 2 act on each element, and [a; b] concatenates.
  • Indices start at 1, except in CasADi methods that take the index of an input or output, such as casadi.sparsity_out(f, 0).
  • A chained comparison such as -2 <= w[1] <= 2 is not a constraint, since Julia evaluates it with &&; write bounded(-2, w[1], 2).

Generate code from a CasADi function

CasADiCodegen.CasadiFunction — Type
CasadiFunction(name, inputs, outputs[, options])

Make a CasADi function from the symbolic inputs and outputs, vectors of SX or MX. CasadiFunction is the front end's name for CasADiCodegen.Function, exported because a bare Function is Julia's abstract function type. options is a Dict of CasADi options, such as "allow_free" => true.

CasADi throws a SwigError when an output has a symbol that is not an input, unless "allow_free" is set, and build_function refuses such a function.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> f = CasadiFunction("f", [x], [sin(x[1]) * x[2]]);

julia> f(casadi.DM([0.0, 2.0]))
DM(0)
source
CasADiCodegen.casadi_function — Function
casadi_function(name, inputs, outputs; input_names, output_names) -> CasADiCodegen.Function

Make a CasADi function from Symbolics.jl expressions: inputs is a vector of symbols and arrays of symbols, outputs a vector of expressions and arrays of expressions, and each becomes one argument or one result of the function, with the shape of the array. Every symbol of an output must be in inputs. input_names and output_names are vectors of strings, one per input and per output; without them CasADi names the arguments and results. The method exists once Symbolics.jl is loaded.

Throws an ArgumentError if an output has a symbol that is not in inputs, or a complex value. A wrong number of names gives CasADi's SwigError.

Examples

julia> using CasADiCodegen

julia> import Symbolics

julia> Symbolics.@variables x y;

julia> expr = sin(x) * y;

julia> grad = Symbolics.gradient(expr, [x, y]);

julia> f = casadi_function("f", [x, y], [expr, grad]);

julia> g, _ = build_function(f; expression = Val{false});

julia> g(0.0, 2.0)
([0.0], [2.0, 0.0])

Symbolics.jl exports a build_function of its own, so import Symbolics, not using, keeps the build_function of this package unambiguous.

CasADiCodegen.Codegen.build_function — Function
build_function(f; expression = Val{true}, force_SA = false, nonzeros = false,
               vector_columns = true, name = Symbol(name_of_f, "!"),
               chunk_size = nothing, split_above = nothing, nanmath = true,
               expand = true, cache = false, solvers = nothing, optlevel = nothing)

Generate Julia code for the CasADi function f. Return an out-of-place function g(arg1, arg2, ...) and an in-place function g!(res, arg): as one Expr with the two definitions by default, or as the pair (g, g!) of compiled functions with expression = Val{false}.

Both functions take arrays in matrix shape. g returns an output of one column as a vector, and as a matrix with vector_columns = false.

  • g takes one array per input. It returns one array for one output, and a tuple of arrays otherwise. The arrays are SVector and SMatrix when the first argument is a static array, and Vector and Matrix otherwise. A Vector or SVector holds an output of one column, also a scalar. Outputs with more than 1024 elements in all give Vector and Matrix for any argument, with a warning at the first call with a static array.
  • g! fills the arrays of the tuple res from the tuple arg and returns res. An array of res can be a mutable static array and must not share memory with an array of arg, since the code reads the arguments while it writes the results. An array of res or arg needs only the number of elements of its output or input, so a vector and a matrix of one column both serve for a column.
  • A structural zero of an output is set to zero. A structural zero of an input is not read.
  • With SparseArrays.jl loaded, an array of res or arg can be a SparseMatrixCSC with the sparsity pattern of that output or input, which SparseMatrixCSC(sparsity) makes. g! then reads and writes the stored values only. Do not change the index vectors of a matrix in place.

Keywords

  • expression = Val{true}: Val{true} returns an Expr, and Val{false} returns compiled functions.
  • force_SA = false: with true, g returns static arrays for any argument.
  • nonzeros = false: with true, return the single function (res, arg) -> res on which the others are built. arg[i] holds the structural nonzeros of input i, and res[j] receives those of output j, as CasADi evaluates a function.
  • vector_columns = true: with false, g returns each output in the shape that CasADi gives it: a column of n elements, and a scalar, become a Matrix of size (n, 1), or an SMatrix{n,1} for a static argument. It does not change g!.
  • name: the name of g! in the returned Expr, a valid identifier. It must end with ! unless nonzeros is set. The name of g is name without !.
  • chunk_size = nothing, split_above = nothing: a function with more than split_above instructions is split into sub-functions of at most chunk_size instructions, which compile faster. chunk_size is 1000 by default. split_above is chunk_size when that is given; otherwise it is 50000 for scalar code and 1000 operations for matrix code. See Speed up compilation of large models.
  • nanmath = true: an operation outside its domain returns NaN through NaNMath.jl, as in CasADi. With false it throws a DomainError, as in Base, and the code accepts any real number type.
  • expand = true: a matrix (MX) function is expanded to scalar operations where CasADi can do that and the expansion does not repeat a called function many times, as the step of an integrator. With false the code keeps the matrix operations. See Scalar code, matrix code and special CasADi functions.
  • cache = false: with true or a directory, the compiled functions come from a package on disk that Julia compiles once, so a later session compiles nothing. A caller that was compiled before the call must call the functions with Base.invokelatest. A Julia function in the graph must belong to a package. See Speed up compilation of large models.
  • optlevel = nothing: with an integer from 0 to 3, Julia compiles the functions at this optimization level, as Base.Experimental.@optlevel sets it, in place of the session's level (-O, 2 by default). With cache it sets the level of the cached package.
  • solvers = nothing: a CasADiCodegen.Solvers with the SciML solvers that the code calls in place of the CasADi solver objects in the graph, since generated code never calls CasADi.

Throws an ArgumentError:

  • when f has free symbols or an operation outside the scope of the package (see Scope and differences from CasADi);
  • when f calls a CasADi solver object that solvers does not replace;
  • when name does not end with ! and nonzeros is not set;
  • with force_SA = true for outputs with more than 1024 elements in all;
  • with cache or optlevel and expression = Val{true}, or an optlevel outside 0 to 3.

g and g! throw an ArgumentError for a wrong number or size of arrays, and g! for an array of res that shares memory with an array of arg.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> y = x[1] * x[2];

julia> f = CasadiFunction("f", [x], [y, jacobian(y, x)]);

julia> g, g! = build_function(f; expression = Val{false});

julia> u = [2.0, 3.0];

julia> g(u)
([6.0], [3.0 2.0])

julia> out = (zeros(1), zeros(1, 2));

julia> g!(out, (u,));

julia> out[2]
1×2 Matrix{Float64}:
 3.0  2.0

CasADiCodegen.Codegen.generate_julia — Function
generate_julia(f, path; module_name, force_SA = false, vector_columns = true,
               name = Symbol(name_of_f, "!"),
               chunk_size = nothing, split_above = nothing, nanmath = true,
               expand = true, solvers = nothing, optlevel = nothing) -> path
generate_julia(f, io::IO; kwargs...) -> nothing

Write Julia source code for the CasADi function f to the file path or to the stream io. The output is one module with the functions of build_function, which describes them.

The module holds:

  • the in-place function name;
  • the out-of-place function, whose name is name without !;
  • the function on nonzeros, f_nonzeros! for a function f;
  • the constants NAME, NAMES_IN, NAMES_OUT, NNZ_IN, NNZ_OUT, NWORK, SPARSITY_IN, SPARSITY_OUT and DEPENDENCIES. Each sparsity pattern is (nrow, ncol, colptr, rowval), 1-based. NWORK is the length of the work vector. DEPENDENCIES is the sorted tuple of the package names that the module imports.

The module does not need CasADiCodegen.jl. A package that includes the file must have each package of DEPENDENCIES as a dependency: StaticArraysCore.jl, and as the code needs them NaNMath.jl, SparseArrays.jl, SpecialFunctions.jl, LinearAlgebra, StaticArrays.jl and the package of each Julia function in a callback, which the module calls by its full name. A function with a SciML integrator, rootfinder or solver gives a module that makes the solvers again, so it also loads CasADiCodegen.jl, SciMLBase.jl and the packages of the algorithms.

Throws an ArgumentError if module_name or name is not a valid identifier, if name does not end with !, or if f has free symbols or an operation outside the package's scope.

Keywords

  • module_name: the name of the module, a valid identifier. The default is the name of f with its first letter in upper case.
  • optlevel = nothing: with an integer from 0 to 3, the module sets its optimization level with Base.Experimental.@optlevel.
  • The other keywords of the signature mean what they mean for build_function.

Examples

generate_julia(f, "f.jl"; module_name = :F)
include("f.jl")
F.f([2.0, 3.0])         # the out-of-place function

Models written as equations

using CasADiCodegen.Models gives these names. SciMLBase.ODEProblem of a System is on SciML problems and functions.

CasADiCodegen.Models — Module
CasADiCodegen.Models

Differential equations written with SX expressions: Differential(t) gives the time derivative of a symbol or an expression, lhs ~ rhs an equation, and System compiles a list of equations into the semi-explicit form that CasADi's integrators take. Load it with using CasADiCodegen.Models.

source
CasADiCodegen.Models.Differential — Type
Differential(t::SX)

The time derivative with respect to the scalar symbol t. D = Differential(t) applies to an SX expression: D(x) of a symbol x is the derivative symbol of x, named "dx", the same symbol at each call, and D(D(x)) is "ddx". D(e) of an expression is the chain rule, D(t) is 1 and D of a number is 0. A matrix gives the matrix of the derivatives of its elements. System sets the derivative of a parameter to 0.

Examples

t = SX.sym("t")
x = SX.sym("x")
D = Differential(t)
D(x^2 + t)    # 2 x dx + 1
source
CasADiCodegen.Models.Equation — Type
Equation(lhs::SX, rhs::SX)
lhs ~ rhs

The equation lhs = rhs of a System. lhs and rhs have the same size, or one of them is a scalar, which stands for each element of the other; a number is a scalar. A matrix gives one scalar equation per element. Broadcasting over Julia vectors of symbols, as in D.(xs) .~ vs, gives a vector of equations.

source
CasADiCodegen.Models.System — Type
System(equations, t; parameters = SX[], name = "system", baumgarte_pole = 0.0)

Compile the Equations equations in the time t into a model in semi-explicit form, x' = ode(x, z, p, t) and 0 = alg(x, z, p, t). The symbols of the equations other than t and parameters are the variables of the model. parameters is a vector of SX symbols, scalar or vector. The model must have one scalar equation per variable, where a variable counts once with all its derivatives.

How `System` compiles the equations, in four steps
  1. An algebraic equation (one without derivatives) that contains linearly a variable y that is not differentiated, with a coefficient that is a number or an expression of the parameters, is solved for y, and y is replaced by its solution in the other equations. y becomes an observed variable; a coefficient of parameters that is zero gives it the value NaN or Inf. This removes the equations of the form a ~ b, a ~ -b and a ~ f(b, c), which connections of parts make.
  2. A variable x whose derivatives appear up to the order n becomes the n differential states x, dx, ..., the derivative symbols of D = Differential(t).
  3. When the equations that contain the derivatives of the highest order are as many as these and linear in them, with a nonsingular coefficient, they are solved for the derivatives, which become observed variables. Otherwise each such derivative becomes an algebraic state, as in exp(D(x)) ~ x.
  4. When the model has algebraic states,

reduce_index reduces it to index 1, with the pole baumgarte_pole. The constraints that the reduction differentiates become invariants, which the initial values must satisfy.

unknowns gives the states of the result, observed the eliminated variables, Dict(sys) the model for casadi.integrator, and SciMLBase.ODEProblem(sys, u0, tspan, p) the SciML problem. Only SX is supported.

Throw an ArgumentError when the number of scalar equations differs from that of the variables, when the elimination leaves an equation without variables, when two symbols of the model have the same name, and when reduce_index refuses the model.

Examples

using CasADiCodegen, CasADiCodegen.Models
t = SX.sym("t")
x = SX.sym("x")
k = SX.sym("k")
D = Differential(t)
sys = System([D(D(x)) ~ -k * x], t; parameters = [k])
unknowns(sys)    # [x, dx]

Julia models traced into CasADi

CasADiCodegen.Codegen.Traced — Type
Traced{S}(value::S) <: Real

A real number that records the operations on it as a CasADi expression of type S, which is SX or MX, so that generic Julia code traces into a CasADi graph.

Arithmetic, the elementary functions, min, max, clamp, ifelse, floor, ceil, trunc, rem, mod, copysign, cbrt, norm and SpecialFunctions.erf, erfc and erfinv give Traced values; a plain number promotes to Traced, a BigFloat as a Float64. CasADi has no complementary error function, so erfc(x) is 1 - erf(x): its relative error is near 1e-12 at x = 3 and 1e-5 at x = 5, and from about x = 6, where erfc is near 2e-17, the value is zero. Its derivative keeps full accuracy. det, inv and A \ b of a square matrix of Traced values are formed by CasADi, since LinearAlgebra's factorizations choose pivots by comparing values. A comparison gives a traced condition, not a Bool, so an if, && or ? : on traced values throws a TypeError instead of following one branch. A condition times a value gives the value or zero, as a Bool does: (x <= 0) * Inf is zero for a positive x. mod and clamp give Julia's results, also for a large quotient, signed zeros and NaN. min and max are CasADi's fmin and fmax, which return the other operand for a NaN, where Julia returns NaN. Use ifelse, min, max or clamp for a choice that depends on the input, or CasADiCodegen.callback for a Julia function with branches.

See CasADiCodegen.traced and CasADiCodegen.untraced.

CasADiCodegen.Codegen.traced_function — Method
traced_function(name, f, u0, p = nothing; inplace = true, time = true, symbolic = SX,
                states = nothing, parameters = nothing) -> CasADiCodegen.Function

Trace the Julia function f of a SciML problem into the CasADi function name(u, p, t), or name(u, p) with time = false, whose result is the derivative or the residual.

f is f(du, u, p, t) in place, or f(u, p, t) out of place with inplace = false, and without t when time = false. It must be generic Julia code, as for traced. It gets the state as an array of Traced values with the shape of u0, and the parameters in the container of p with traced elements: p may be a number, an array of numbers, a tuple or a named tuple of numbers, or nothing for a problem without parameters. In place, du starts at zero.

The arguments of the result are column vectors: u and du hold the elements in the order of vec(u0), and p those of vec(p), or of the tuple, empty for nothing. states and parameters name the scalar symbols of these elements, as vectors of Symbol or String; they become the variable names of a SciML function made from the result (see ODEFunction). By default the parameters of a named tuple have its keys as names, and the other elements are u_0, u_1, ... and p_0, p_1, ... symbolic is SX or MX. A method for a SciML problem comes with SciMLBase.jl.

Examples

using CasADiCodegen
import SciMLBase

decay!(du, u, p, t) = (du .= -p.k .* u)
u0 = [1.0, 2.0]
f = CasADiCodegen.traced_function("decay", decay!, u0, (k = 0.5,); states = [:x, :y])
rhs = SciMLBase.ODEFunction(f)
tspan = (0.0, 1.0)
p = [0.5]
problem = SciMLBase.ODEProblem(rhs, u0, tspan, p)
source
CasADiCodegen.Codegen.traced_function — Method
CasADiCodegen.traced_function(name, problem; symbolic = SX, states = nothing, parameters = nothing) -> CasADiCodegen.Function

Trace the function of the SciML problem, an ODEProblem or a NonlinearProblem, into a CasADi function, with the shapes of its initial state and of its parameters (see traced_function). The function of an ODEProblem takes the time; that of a NonlinearProblem does not. The in-place or out-of-place form is that of the problem. Parameters of the type SciMLBase.NullParameters count as none.

The names of the states and of the parameters are states and parameters when given, else those of the symbolic system of the problem, such as a SciMLBase.SymbolCache with one name per element, else the keys of a named tuple of parameters, else u_0, u_1, ... and p_0, p_1, ...

Examples

tspan = (0.0, 11.5)
original = SciMLBase.ODEProblem(brusselator!, u0, tspan, p)
rhs = CasADiCodegen.traced_function("brusselator", original)
f = SciMLBase.ODEFunction(rhs; sparse = true)
problem = SciMLBase.ODEProblem(f, vec(u0), tspan, p)
source
CasADiCodegen.Codegen.traced_problem — Method
CasADiCodegen.traced_problem(name, problem; symbolic = SX, states = nothing, parameters = nothing, options...)

Return the SciML problem of the same kind as problem, an ODEProblem or a NonlinearProblem, whose function is generated code for the function of problem, traced into the CasADi function name by traced_function, together with its analytic Jacobian.

The new problem keeps the initial state, with its shape, the time span, the mass matrix and the keywords of problem, such as saveat or callback. Its parameters are the values of those of problem as a vector, in their order (vec(p) for an array), or none for SciMLBase.NullParameters; a kept callback that reads a field of a tuple of parameters must read the vector by place or by name instead. The states and the parameters have names, as described for traced_function, so that solution[:x] and remake(problem; p = [:k => 2.0]) work. A static vector state gives out-of-place functions that return static arrays.

The options go to ODEFunction or to NonlinearFunction, such as sparse = true for a sparse Jacobian (with SparseArrays.jl loaded) or jac = false. The other fields of the function of problem, such as a jac or an analytic solution, are not kept.

Examples

using CasADiCodegen
import SciMLBase

decay!(du, u, p, t) = (du .= -p.k .* u)
u0 = [1.0, 2.0]
tspan = (0.0, 1.0)
p = (k = 0.5,)
original = SciMLBase.ODEProblem(decay!, u0, tspan, p; saveat = 0.1)
problem = CasADiCodegen.traced_problem("decay", original)
problem.p, problem.f.jac(problem.u0, problem.p, 0.0)

Julia functions inside a model

CasADiNative.callback — Method
callback(f, name, sizes_in, sizes_out; jacobian = nothing, options...) -> CasADiCodegen.Function

Make the Julia function f a CasADi function that a matrix (MX) graph can call. Code from build_function and generate_julia calls f and its Jacobian directly, with no CasADi in between.

Arguments

  • f: a function that takes one array per size in sizes_in. It returns one array, or a tuple with one array per size in sizes_out. A result can be any array with the right number of elements, for example a static array.
  • name: the name of the CasADi function, a valid identifier.
  • sizes_in, sizes_out: tuples with one size per argument and per result. A size is an integer n or a tuple (n,) for a vector, which f receives as a Vector, or a tuple (rows, columns) for a matrix.

Keywords

  • jacobian = nothing: how CasADi differentiates f.
    • nothing: no derivative.
    • A Julia function with the arguments of f. It returns the Jacobian matrix, or a tuple with one matrix per pair of result and argument, ordered by result first.
    • A tuple of such functions, for derivatives of higher order. Each function returns the Jacobian blocks of the function before it: one matrix per pair of a block and an argument, ordered by block first. A block counts as the vector of its elements in column-major order.
    • An ADTypes.jl backend, such as AutoForwardDiff(), for any order. Load DifferentiationInterface.jl and the package of the backend.
  • options...: CasADi options for the function, for example enable_fd = true.

generate_julia needs f and the Jacobian functions to be named functions of a module. The package keeps each callback for the rest of the session, since a CasADi graph can call it after its last Julia reference is gone; one costs about 2 kB. See Call a Julia function from the model.

Examples

julia> using CasADiCodegen

julia> square(v) = v .^ 2;

julia> square_jacobian(v) = [2v[1] 0; 0 2v[2]];

julia> c = callback(square, "square", (2,), (2,); jacobian = square_jacobian);

julia> v = MX.sym("v", 2);

julia> y = c(v);

julia> f = CasadiFunction("f", [v], [y, jacobian(y, v)]);

julia> g, g! = build_function(f; expression = Val{false});

julia> g([3.0, 4.0])
([9.0, 16.0], [6.0 0.0; 0.0 8.0])

SciML solvers inside a model

integrator and rootfinder come from the CasADi front end. With a solver name such as "cvodes" or "kinsol", they make a CasADi solver object, as in Python. The methods below take a SciML algorithm instead. They exist once SciMLBase.jl is loaded, which every SciML solver package does.

CasADiNative.integrator — Method

  • specialize = SciMLBase.FullSpecialize: with SciMLBase.AutoSpecialize the solver is compiled once for all integrators, and the runs are slower.

CasADiCodegen.Codegen.linearization — Function

Generate code that linearizes the state-space model x' = f(x, u, p), y = h(x, u, p) about a point. lin(x, u, p) returns the matrices (A, B, C, D) at the point (x, u, p), so that the deviations δ from it satisfy δx' ≈ A δx + B δu and δy ≈ C δx + D δu. CasADiCodegen.Codegen.linearization_function — Function
linearization_function(f, h; sparse = false) -> CasADiCodegen.Function
linearization_function(f, g, h; sparse = false) -> CasADiCodegen.Function

Return the CasADi function (x, u, p) -> (A, B, C, D) of the linearization of the state-space model x' = f(x, u, p), y = h(x, u, p), with A of size nx × nx, B of nx × nu, C of ny × nx and D of ny × nu for x, u and y of the sizes nx, nu and ny:

\[A = ∂f/∂x, \quad B = ∂f/∂u, \quad C = ∂h/∂x, \quad D = ∂h/∂u.\]

f and h are CasADi functions of the column vectors x, u and p, with one column vector as their result; f has the size of x. For a model without parameters, p has no elements. The matrices are dense; with sparse = true they keep the sparsity patterns of the Jacobians. linearization gives the generated code of this function.

With three functions of (x, z, u, p), the model is the differential-algebraic system x' = f(x, z, u, p), 0 = g(x, z, u, p), y = h(x, z, u, p) with the algebraic states z, and the result is the function (x, z, u, p) -> (A, B, C, D). The result of g has the size of z. The matrices are those of the model at a point where g = 0 and ∂g/∂z is invertible, which need not be a steady state. The caller ensures both conditions: they are not checked, and at a point where g ≠ 0 the matrices do not describe the model.

How the algebraic states are eliminated

The implicit function theorem eliminates the algebraic states: with M = (∂g/∂z) \ [∂g/∂x ∂g/∂u],

\[[A \; B] = [∂f/∂x \; ∂f/∂u] - (∂f/∂z) M, \quad [C \; D] = [∂h/∂x \; ∂h/∂u] - (∂h/∂z) M.\]

CasADiCodegen.Codegen.reduce_index — Function
reduce_index(dae; baumgarte_pole = 0.0) -> NamedTuple

Reduce the semi-explicit differential-algebraic equation dae to index 1 by differentiating its algebraic equations, with Pantelides' structural algorithm. Return (; dae, invariants, differentiations, index).

dae is a dictionary in the form that CasADi's integrators take, with SX or MX values that are dense column vectors: the differential states "x", the algebraic states "z", the parameters "p", the scalar time "t", and the expressions "ode", the derivative of x, and "alg", the algebraic equations 0 = alg, of the size of z. "x", "z" and "t" are symbols or concatenations of symbols. "p" and "t" are optional, and so are "z" and "alg" together.

The result dae has the same form, and casadi.integrator with a DAE plugin such as "idas" accepts it. Equation alg[i] is replaced by its time derivative of order differentiations[i], in which the derivative of x is replaced by ode. An algebraic state z[j] whose derivative enters these equations becomes a differential state, and its derivative a new symbol that takes its place in z. The states of the result are x, then for each such z[j], in the order of z, the state and its derivatives below the highest. A derivative is named "d" followed by the name of the symbol. For T differentiated twice, for example, the result has the states [x; T; dT] with the derivative [ode; dT; ddT], and ddT in z. The element k of an MX vector symbol z is first replaced by the scalar symbol z_k, counted from 0, as the elements of an SX vector symbol are named, so a function of the result takes dae["x"] and dae["z"] of the result, not the original symbols.

invariants is the column of the replaced equations and of their derivatives of lower order, by equation and then by order, in the symbols of the result. They are zero along a solution that starts where they are zero, but the reduced equations do not enforce them, so a numerical solution drifts away from them. A consistent initial point satisfies invariants and alg. index is the differentiation index: 0 with no algebraic equation, otherwise 1 plus the largest number of differentiations.

A model of index 1 is returned unchanged, with differentiations all 0 and no invariant.

Keywords

  • baumgarte_pole = 0.0: the pole γ ≤ 0 of Baumgarte's stabilization. An equation g differentiated k times becomes the combination of its derivatives whose characteristic polynomial is (s - γ)^k, so that its invariants decay as exp(γ t) instead of drifting; 0 gives the derivative of order k alone.

Throws an ArgumentError for a positive baumgarte_pole, when the equations are structurally singular (no number of differentiations determines the states; the message names the equations ode[i] and alg[i] involved, from 1), and when terms of a derivative cancel so that the reduced equations do not determine z.

The algorithm selects no dummy derivatives: the reduced model keeps every state and enforces only the highest derivative of each equation, so the invariants drift unless they are stabilized. See Model a circuit and a pendulum as DAEs.

julia> pendulum = Dict("x" => vcat(q, v), "z" => T, "ode" => ode, "alg" => alg);

CasADiCodegen.Codegen.nonsmooth_operations — Function
nonsmooth_operations(f; inputs = nothing, expand = true) -> Vector{Pair{Symbol,Int}}

Count the switching surfaces in the CasADi function f whose operand depends on inputs, by operation. Return the pairs operation => count, the most frequent first. An operation is CasADi's operation code, such as :OP_SIGN, or the class of a called function.

A switching surface is an operation whose derivative CasADi takes branch by branch, at a jump of the value or a kink of the slope.

Which operations count as switching surfaces
  • a jump of the value: < and > (both :OP_LT), <= and >= (:OP_LE), sign, floor, ceil, fmod, remainder, the sign operand of copysign (:OP_COPYSIGN), and the index of conditional (:Switch);

Equality tests and logical operations are not counted. An if_else or a conditional whose condition is a comparison counts once, at the comparison.

inputs is nothing for all inputs, an input place from 1 or an input name, or a collection of them. With expand = true an MX function is first expanded to scalar code when CasADi can expand it; otherwise a matrix counts as depending on every input of any of its elements. The bodies of Julia callbacks and external functions are not scanned.

Throws ArgumentError for an input that f does not have.

CasADiCodegen.Codegen.instruction_histogram — Function
instruction_histogram(f; expand = true) -> Vector{Pair{Symbol,Int}}

Count the instructions of the code that build_function emits for the CasADi function f, by operation. Return the pairs operation => count, the most frequent first.

Matrix code counts the instructions of f itself, not those of the functions that it calls. expand is the keyword of build_function.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> y = sin(x[1]) * x[2] + x[1] * x[2];

julia> f = CasadiFunction("f", [x], [y]);

julia> CasADiCodegen.instruction_histogram(f)
5-element Vector{Pair{Symbol, Int64}}:
  :OP_INPUT => 2
    :OP_MUL => 2
    :OP_ADD => 1
 :OP_OUTPUT => 1
    :OP_SIN => 1

CasADiCodegen.Codegen.nan_trace — Function
nan_trace(f, arguments...) -> NamedTuple or nothing

Find where the first NaN appears when the CasADi function f runs on numbers. Return the first instruction of the scalar code of f whose result is NaN while no operand is, or the first NaN among the arguments. Return nothing when there is no NaN.

Give one argument per input: an array with the shape of the input, or the vector of its structural nonzeros. CasADi must be able to expand f to scalar code, so f cannot call a Julia function.

The result has these fields:

  • instruction: the place of the instruction in the scalar code.
  • operation: the operation, for example :OP_SQRT.
  • operands: the values of the operands.
  • result: the result of the operation.
  • text: the operation on those values, or the place of the NaN in the arguments.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> f = CasadiFunction("f", [x], [sqrt(x[1]) + x[2]]);

julia> CasADiCodegen.nan_trace(f, [-1.0, 2.0])
(instruction = 2, operation = :OP_SQRT, operands = (-1.0,), result = NaN, text = "NaNMath.sqrt(-1.0)")

julia> CasADiCodegen.nan_trace(f, [1.0, 2.0]) === nothing
true
