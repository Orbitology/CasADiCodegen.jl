API reference

This page and SciML problems and functions list the functions and types of CasADiCodegen.jl, grouped by task. The package exports build_function, generate_julia, CasadiFunction and casadi_function, and using CasADiCodegen also gives the names that the front end of CasADi exports, such as SX, MX, DM, Opti, jacobian, gradient and substitute. The whole front end, with the functions of the Python API of CasADi, is the module CasADiCodegen.C, and a CasADi function is a CasADiCodegen.Function, which CasadiFunction makes. The other names of these pages need the prefix CasADiCodegen., except callback, integrator and rootfinder, which are exported functions of the front end to which the package adds methods; the entries below write the prefix for all of them.

Code generation

CasADiCodegen.CasadiFunction — Type
CasadiFunction(name, inputs, outputs[, options])

Make a function of CasADi from the symbolic inputs and outputs. CasadiFunction is the front end's name for CasADiCodegen.Function, exported because a bare Function is the abstract type of Julia.

x = SX.sym("x", 2)
f = CasadiFunction("f", [x], [sin(x[1]) * x[2]])
source
CasADiCodegen.casadi_function — Function
casadi_function(name, inputs, outputs; input_names, output_names) -> CasADiCodegen.Function

Make a function of CasADi from Symbolics.jl expressions: inputs is a vector of symbols and arrays of symbols, outputs a vector of expressions and arrays of expressions, and each becomes one argument or one result of the function, with the shape of the array. Every symbol of an output must be in inputs. input_names and output_names are vectors of strings; without them CasADi names the arguments and results. The method is defined when Symbolics.jl is loaded.

using Symbolics
@variables x y
f = casadi_function("f", [x, y], [sin(x) * y, Symbolics.gradient(sin(x) * y, [x, y])])

CasADiCodegen.Codegen.build_function — Function
build_function(f; expression = Val{true}, force_SA = false, nonzeros = false,
               vector_columns = true, name = Symbol(name_of_f, "!"),
               chunk_size = nothing, split_above = nothing,
               nanmath = true, expand = true, cache = false, solvers = nothing, optlevel = nothing)

Generate Julia code for the CasADi function f, in the manner of Symbolics.build_function. Return an out-of-place function g(arg1, arg2, ...) and an in-place function g!(res, arg): as one Expr with the two definitions by default, or as the pair (g, g!) of compiled functions with expression = Val{false}.

Both functions take arrays in matrix shape. CasADi has no vector type, so every output is a matrix; g returns one of one column as a vector by default, and as a matrix with vector_columns = false.

  • g takes one array per input. It returns one array for one output, and a tuple of arrays otherwise. The arrays are SVector and SMatrix when the first argument is a static array, and Vector and Matrix otherwise. A Vector or SVector holds an output of one column, also a scalar. Outputs with more than 1024 elements in all give Vector and Matrix for any argument, with a warning at the first call with a static array.
  • g! fills the arrays of the tuple res from the tuple arg and returns res. An array of res can be a mutable static array. An array of res or arg needs the number of elements of its output or input only, so a vector and a matrix of one column both serve for a column.
  • A structural zero of an output is set to zero. A structural zero of an input is not read.
  • With SparseArrays.jl loaded, an array of res or arg can be a SparseMatrixCSC with the sparsity pattern of that output or input, which SparseMatrixCSC(sparsity) makes. g! then reads and writes the stored values only. It compares the whole pattern of a matrix whose index vectors (colptr and rowval) are not those of the last matrix that passed this comparison. Otherwise it compares the number of rows and of stored values only, so a call costs as much as the function on nonzeros. Do not change the index vectors of a matrix in place.

f must have no free symbols and only supported operations; see Scope and differences from CasADi.

Keywords

  • expression = Val{true}: Val{true} returns an Expr, and Val{false} returns compiled functions.
  • force_SA = false: with true, g returns static arrays for any argument. It throws an ArgumentError for outputs with more than 1024 elements in all.
  • nonzeros = false: with true, return the single function (res, arg) -> res on which the others are built. arg[i] holds the structural nonzeros of input i, and res[j] receives those of output j, as CasADi evaluates a function.
  • vector_columns = true: with false, g returns each output in the shape that CasADi gives it: a column of n elements, and a scalar, become a Matrix of size (n, 1), or an SMatrix{n,1} for a static argument. A function whose outputs then have a fixed number of dimensions, such as the matrices of a linearization, needs this. It does not change g! or the function of nonzeros.
  • name: the name of g! in the returned Expr, a valid identifier. It must end with ! unless nonzeros is set. The name of g is name without !.
  • chunk_size = nothing, split_above = nothing: a function with more than split_above instructions is split into sub-functions of at most chunk_size instructions. This shortens the compilation of a large function and costs some speed. chunk_size is 1000 by default. split_above is chunk_size when that is given; otherwise it is 50000 for scalar code and 1000 operations for matrix code. See Large functions and the cache on disk.
  • nanmath = true: an operation outside its domain returns NaN through NaNMath.jl, as in CasADi. With false it throws a DomainError, as in Base, and the code accepts any real number type.
  • expand = true: a matrix (MX) function is expanded to scalar operations where CasADi can do that. With false the code keeps the matrix operations. See Matrix code and functions without instructions.
  • cache = false: with true or a directory, the compiled functions come from a package on disk that Julia compiles once, so a later session compiles nothing. It needs expression = Val{false}. Code that runs already must call the functions with Base.invokelatest. A Julia function in the graph must belong to a package. See Large functions and the cache on disk.
  • optlevel = nothing: with an integer from 0 to 3, Julia compiles the functions at this optimization level, as Base.Experimental.@optlevel sets it, in place of the level of the session (-O, 2 by default). A lower level shortens the compilation at the first call of a large function and can slow the later calls. It needs expression = Val{false}, and with cache it sets the level of the cached package.
  • solvers = nothing: a CasADiCodegen.Solvers with the SciML solvers that the code calls in place of the solver objects of CasADi in the graph. Generated code never calls CasADi, so such an object with no solver throws an ArgumentError.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> f = CasadiFunction("f", [x], [x[1] * x[2], jacobian(x[1] * x[2], x)]);

julia> g, g! = build_function(f; expression = Val{false});

julia> g([2.0, 3.0])
([6.0], [3.0 2.0])

julia> out = (zeros(1), zeros(1, 2));

julia> g!(out, ([2.0, 3.0],));

julia> out[2]
1×2 Matrix{Float64}:
 3.0  2.0

CasADiCodegen.Codegen.generate_julia — Function
generate_julia(f, path; module_name, force_SA = false, vector_columns = true,
               name = Symbol(name_of_f, "!"),
               chunk_size = nothing, split_above = nothing, nanmath = true,
               expand = true, solvers = nothing, optlevel = nothing) -> path
generate_julia(f, io::IO; kwargs...) -> nothing

Write Julia source code for the CasADi function f to the file path or to the stream io, as CasADi generate writes C code. The output is one module with the functions of build_function, which describes them.

The module holds:

  • the in-place function name;
  • the out-of-place function, whose name is name without !;
  • the function on nonzeros, whose name is that name followed by _nonzeros!;
  • the constants NAME, NAMES_IN, NAMES_OUT, NNZ_IN, NNZ_OUT, NWORK, SPARSITY_IN, SPARSITY_OUT and DEPENDENCIES. Each sparsity pattern is (nrow, ncol, colptr, rowval), 1-based. NWORK is the length of the work vector. DEPENDENCIES is the sorted tuple of the names of the packages that the module imports.

The module does not need CasADiCodegen.jl. A package that includes the file must have each package of DEPENDENCIES as a dependency. The module imports:

  • StaticArraysCore.jl, for the method with static arrays, unless f has no input;
  • NaNMath.jl, when the code has an operation with a limited domain, such as sqrt or log, unless nanmath = false;
  • SparseArrays.jl, when an input or an output has structural zeros, as most Jacobians have, for the methods with sparse matrices;
  • SpecialFunctions.jl for erfinv, LinearAlgebra for the factorizations of matrix code, StaticArrays.jl and the package of each Julia function of a callback.

A Julia function of a callback must be a named function of a module. The module calls it by its full name and imports its package.

A function with an integrator, a rootfinder or an optimization solver of the SciML extension gives a module that makes the solvers again. That module loads CasADiCodegen.jl, SciMLBase.jl and the packages of the algorithm, which must be installed.

Keywords

  • module_name: the name of the module, a valid identifier. The default is the name of f with its first letter in upper case.
  • optlevel = nothing: with an integer from 0 to 3, the module sets its optimization level with Base.Experimental.@optlevel.
  • The other keywords of the signature have the meaning that build_function gives them.

Examples

generate_julia(f, "f.jl"; module_name = :F)
include("f.jl")
F.f([2.0, 3.0])         # the out-of-place function

Models written as equations

The submodule CasADiCodegen.Models exports these names, which using CasADiCodegen.Models gives; SciMLBase.ODEProblem of a System is on SciML problems and functions.

CasADiCodegen.Models — Module
CasADiCodegen.Models

Differential equations written as equations of SX expressions: Differential(t) gives the time derivative of a symbol or an expression, lhs ~ rhs an equation, and System compiles a list of equations into the semi-explicit form of the CasADi integrators. Load it with using CasADiCodegen.Models.

source
CasADiCodegen.Models.Differential — Type
Differential(t::SX)

The time derivative by the scalar symbol t. D = Differential(t) applies to an SX expression: D(x) of a symbol x is the derivative symbol of x, named "dx", the same symbol at each call, and D(D(x)) is "ddx". D(e) of an expression is the chain rule, D(t) is 1 and D of a number is 0. A matrix gives the matrix of the derivatives of its elements. System sets the derivative of a parameter to 0.

Examples

t, x = SX.sym("t"), SX.sym("x")
D = Differential(t)
D(x^2 + t)    # 2 x dx + 1
source
CasADiCodegen.Models.Equation — Type
Equation(lhs::SX, rhs::SX)
lhs ~ rhs

The equation lhs = rhs of a System. lhs and rhs have one size, or one of them is a scalar, which stands for each element of the other; a number is a scalar. A matrix gives one scalar equation per element. Broadcasting over Julia vectors of symbols, as in D.(xs) .~ vs, gives a vector of equations.

source
CasADiCodegen.Models.System — Type
System(equations, t; parameters = SX[], name = "system", baumgarte_pole = 0.0)

Compile the Equations equations in the time t into a model in semi-explicit form, x' = ode(x, z, p, t) and 0 = alg(x, z, p, t). The symbols of the equations other than t and parameters are the variables of the model. parameters is a vector of SX symbols, scalar or vector. The model must have one scalar equation per variable, where a variable counts once with all its derivatives.

The compilation takes four steps:

  1. An algebraic equation (one without derivatives) with a variable y that is not differentiated and that it contains linearly, with a coefficient that is a number or an expression of the parameters, is solved for y, and y is replaced by its solution in the other equations. y becomes an observed variable; a coefficient of parameters that is zero gives it the value NaN or Inf. This removes the equations of the form a ~ b, a ~ -b and a ~ f(b, c), which connections of parts make.
  2. A variable x whose derivatives appear up to the order n becomes the n differential states x, dx, ..., the derivative symbols of D = Differential(t).
  3. When the equations that contain the derivatives of the highest order are as many as these and linear in them, with a nonsingular coefficient, they are solved for the derivatives, which become observed variables. Otherwise each such derivative becomes an algebraic state, as in exp(D(x)) ~ x.
  4. When the model has algebraic states, reduce_index reduces it to index 1, with the pole baumgarte_pole. The constraints that the reduction differentiates become invariants, which the initial values must satisfy.

unknowns gives the states of the result, observed the eliminated variables, Dict(sys) the model for CasADiCodegen.C.integrator, and SciMLBase.ODEProblem(sys, u0, tspan, p) the SciML problem. Only SX is supported.

Throw an ArgumentError when the number of scalar equations differs from that of the variables, when the elimination leaves an equation without variables, when two symbols of the model have one name, and when reduce_index refuses the model.

Examples

using CasADiCodegen, CasADiCodegen.Models
t, x, k = SX.sym("t"), SX.sym("x"), SX.sym("k")
D = Differential(t)
sys = System([D(D(x)) ~ -k * x], t; parameters = [k])
unknowns(sys)    # [x, dx]
source

Julia models traced into CasADi

CasADiCodegen.Codegen.Traced — Type
Traced{S}(value::S) <: Real

A real number that records the operations on it as a CasADi expression of type S, which is SX or MX, so that generic Julia code traces into a CasADi graph.

Arithmetic, the elementary functions, min, max, clamp, ifelse, floor, ceil, trunc, rem, mod, copysign, cbrt and norm give Traced values; a plain number promotes to Traced. det, inv and A \ b of a square matrix of Traced values are formed by CasADi, since the factorizations of LinearAlgebra choose pivots by comparing values. A comparison gives a traced condition, not a Bool, so an if, && or ? : on traced values throws a TypeError instead of following one branch. Use ifelse, min, max or clamp for a choice that depends on the input, or CasADiCodegen.callback for a Julia function with branches.

See CasADiCodegen.traced and CasADiCodegen.untraced.

source
CasADiCodegen.Codegen.traced — Function
traced(x::Union{SX,MX}) -> Vector{Traced}

Return the elements of the symbolic column vector x as a vector of CasADiCodegen.Traced, the argument of a generic Julia function to trace.

Examples

using CasADiCodegen, LinearAlgebra

acceleration(r, μ) = -μ * r / norm(r)^3          # generic Julia code

a = acceleration(CasADiCodegen.traced(r), 398600.4418)
f = CasadiFunction("a", [r], [CasADiCodegen.untraced(a)])

CasADiCodegen.Codegen.traced_function — Method
traced_function(name, f, u0, p = nothing; inplace = true, time = true, symbolic = SX,
                states = nothing, parameters = nothing) -> CasADiCodegen.Function

Trace the Julia function f of a SciML problem into the CasADi function name(u, p, t), or name(u, p) with time = false, whose result is the derivative or the residual.

f is f(du, u, p, t) in place, or f(u, p, t) out of place with inplace = false, and without t when time = false. It must be generic Julia code, as for traced. It gets the state as an array of Traced values with the shape of u0, and the parameters in the container of p with traced elements: p may be a number, an array of numbers, a tuple or a named tuple of numbers, or nothing for a problem without parameters. In place, du starts at zero.

The arguments of the result are column vectors: u and du hold the elements in the order of vec(u0), and p those of vec(p), or of the tuple, empty for nothing. states and parameters name the scalar symbols of these elements, as vectors of Symbol or String; the names become those of the variables of a SciML function made from the result (see ODEFunction). By default the parameters of a named tuple have its keys as names, and the other elements are u_0, u_1, ... and p_0, p_1, ... symbolic is SX or MX. A method for a SciML problem comes with SciMLBase.jl.

Examples

using CasADiCodegen
import SciMLBase

decay!(du, u, p, t) = (du .= -p.k .* u)
f = CasADiCodegen.traced_function("decay", decay!, [1.0, 2.0], (k = 0.5,); states = [:x, :y])
problem = SciMLBase.ODEProblem(SciMLBase.ODEFunction(f), [1.0, 2.0], (0.0, 1.0), [0.5])
source
CasADiCodegen.Codegen.traced_function — Method
CasADiCodegen.traced_function(name, problem; symbolic = SX, states = nothing, parameters = nothing) -> CasADiCodegen.Function

Trace the function of the SciML problem, an ODEProblem or a NonlinearProblem, into a CasADi function, with the shapes of its initial state and of its parameters (see traced_function). The function of an ODEProblem takes the time; that of a NonlinearProblem does not. The in-place or out-of-place form is that of the problem. Parameters of the type SciMLBase.NullParameters count as none.

The names of the states and of the parameters are states and parameters when given, else those of the symbolic system of the problem, such as a SciMLBase.SymbolCache with one name per element, else the keys of a named tuple of parameters, else u_0, u_1, ... and p_0, p_1, ...

Examples

original = SciMLBase.ODEProblem(brusselator!, u0, (0.0, 11.5), p)
rhs = CasADiCodegen.traced_function("brusselator", original)
f = SciMLBase.ODEFunction(rhs; sparse = true)
problem = SciMLBase.ODEProblem(f, vec(u0), (0.0, 11.5), p)
source
CasADiCodegen.Codegen.traced_problem — Method
CasADiCodegen.traced_problem(name, problem; symbolic = SX, states = nothing, parameters = nothing, options...)

Return the SciML problem of the same kind as problem, an ODEProblem or a NonlinearProblem, whose function is generated code for the function of problem, traced into the CasADi function name by traced_function, together with its analytic Jacobian.

The new problem keeps the initial state, with its shape, the time span, the mass matrix and the keywords of problem, such as saveat or callback. Its parameters are the values of those of problem as a vector, in their order (vec(p) for an array), or none for SciMLBase.NullParameters; a kept callback that reads a field of a tuple of parameters must read the vector by place or by name instead. The states and the parameters have names, as described for traced_function, so that solution[:x] and remake(problem; p = [:k => 2.0]) work. A static vector state gives functions out of place that return static arrays.

The options go to ODEFunction or to NonlinearFunction, such as sparse = true for a sparse Jacobian (with SparseArrays.jl loaded) or jac = false. The other fields of the function of problem, such as a jac or an analytic solution, are not kept.

Examples

using CasADiCodegen
import SciMLBase

decay!(du, u, p, t) = (du .= -p.k .* u)
original = SciMLBase.ODEProblem(decay!, [1.0, 2.0], (0.0, 1.0), (k = 0.5,); saveat = 0.1)
problem = CasADiCodegen.traced_problem("decay", original)
problem.p, problem.f.jac(problem.u0, problem.p, 0.0)

Julia functions inside a model

CasADiNative.callback — Method
callback(f, name, sizes_in, sizes_out; jacobian = nothing, options...) -> CasADiCodegen.Function

Make the Julia function f a CasADi function that a matrix (MX) graph can call. Code from build_function and generate_julia calls f and its Jacobian directly, with no CasADi in between.

Arguments

  • f: a function that takes one array per size of sizes_in. It returns one array, or a tuple with one array per size of sizes_out. A result can be any array with the right number of elements, for example a static array.
  • name: the name of the CasADi function, a valid identifier.
  • sizes_in, sizes_out: tuples with one size per argument and per result. A size is an integer n or a tuple (n,) for a vector, which f receives as a Vector, or a tuple (rows, columns) for a matrix.

Keywords

  • jacobian = nothing: how CasADi differentiates f.
    • nothing: no derivative.
    • A Julia function with the arguments of f. It returns the Jacobian matrix, or a tuple with one matrix per pair of result and argument, ordered by result first.
    • A tuple of such functions, for derivatives of higher order. Each function returns the Jacobian blocks of the function before it: one matrix per pair of a block and an argument, ordered by block first. A block counts as the vector of its elements in column-major order.
    • An ADTypes.jl backend, such as AutoForwardDiff(), for any order. Load DifferentiationInterface.jl and the package of the backend.
  • options...: options of CasADi for the function, for example enable_fd = true.

generate_julia needs f and the Jacobian functions to be named functions of a module. See Call a Julia function from the model.

Examples

julia> using CasADiCodegen

julia> square(v) = v .^ 2;

julia> c = callback(square, "square", (2,), (2,); jacobian = v -> [2v[1] 0; 0 2v[2]]);

julia> v = MX.sym("v", 2);

julia> f = CasadiFunction("f", [v], [c(v), jacobian(c(v), v)]);

julia> g, g! = build_function(f; expression = Val{false});

julia> g([3.0, 4.0])
([9.0, 16.0], [6.0 0.0; 0.0 8.0])

SciML solvers inside a model

integrator and rootfinder are the functions of the CasADi front end. With a solver name such as "cvodes" or "kinsol", they make a solver object of CasADi itself, as in Python. The methods below take a SciML algorithm instead; they exist once SciMLBase.jl is loaded, which each SciML solver package does.

CasADiNative.integrator — Method
integrator(name, alg, dae, t0, tf; specialize, adjoint = false, mass, nonsmooth = :warn,
           modes = nothing, switches = nothing, switch_times = false, options...) -> CasADiCodegen.Function
integrator(name, alg, dae, t0, times::AbstractVector; specialize, adjoint = false, nonsmooth = :warn,
           modes = nothing, switches = nothing, options...) -> CasADiCodegen.Function
integrator(name, alg, dae; specialize, adjoint = false, mass, direction = 0, interp_points = 10,
           events = 1, terminal = true, exact = true, nonsmooth = :warn,
           modes = nothing, switches = nothing, switch_times = false, options...) -> CasADiCodegen.Function

Make a CasADi function that integrates an ordinary differential equation with the SciML algorithm alg, for example Vern9() of OrdinaryDiffEqVerner.jl. CasADi differentiates the function to any order, and build_function emits code that calls the solver directly.

The times select the form of the function. p is absent when the model has no parameters.

CallFunctionResult
integrator(name, alg, dae, t0, tf)F(x0, p)the state at tf
integrator(name, alg, dae, t0, times)F(x0, p)a matrix; column k is the state at times[k]
integrator(name, alg, dae)G(x0, p, t0, tf)the state at tf; CasADi also differentiates by the two times

With free times, tf can be before t0 or equal to it. The times of the vector times can be in any order and on both sides of t0. One run of the solver, which stops at each time, gives the states at all the times after t0, and one more those before it; options must not hold a saving option, such as saveat or tstops. A model with quadratures returns them as a second result.

Arguments

  • name: the name of the CasADi function, a valid identifier.
  • dae: a dictionary as for the CasADi integrators. It holds the state "x" and its derivative "ode", both dense column vectors. Optional entries are the parameters "p", the time "t" and the integrands "quad". With free times, the entry "zero" is a column of event functions, and "transition" is the state after an event: one column, or one column per event function.
  • t0, tf, times: finite times. t0 and tf must be different.

Keywords

  • specialize = SciMLBase.FullSpecialize: the specialization of the SciML problem. With SciMLBase.AutoSpecialize the solver is compiled once for all integrators, and the runs are slower.
  • adjoint = false: with true, a reverse derivative comes from an integrator of the adjoint equations, which runs from the final time back to the initial time. Its cost does not grow with the number of parameters.
  • mass: the diagonal of the mass matrix of a model with algebraic states: 0 for an algebraic state and 1 for the others. The element of "ode" for an algebraic state is the residual of an algebraic equation, and its initial value is a guess. alg must accept a mass matrix, as Rodas5P() of OrdinaryDiffEqRosenbrock.jl does. A vector of times is not supported with it.
  • direction = 0: the change of sign of an element of "zero" that is an event: any with 0, from negative to positive with 1, and from positive to negative with -1.
  • interp_points = 10: the number of points of each step at which the solver looks for the change of sign, besides the end of the step.
  • events = 1: the number of events that the integration passes.
  • terminal = true: the integration ends at the last event. With false it applies the transition there too and goes on to tf.
  • exact = true: a call throws when fewer than events events come before tf. With false it passes at most events events and returns their count.
  • nonsmooth = :warn: what a switch in "ode" or "quad" gives when its operand depends on the state, or on the time and a parameter together: a warning when the integrator is built, an ArgumentError with :error, or nothing with :ignore. A switch is an operation such as a comparison, sign or abs; Discontinuous models lists them all. The values are right, but CasADi differentiates such an operation branch by branch, so the derivatives miss the jump of the state transition matrix (STM) at the switching time.
  • modes = nothing: the pair m => S of a model that switches between modes. m is a column of symbols of the type of the state, which "ode" and "quad" use in place of the sign of the switching functions S, a column of the same size: a mode is +1 where its switching function is positive and -1 where it is negative. Each change of sign of S is an event that flips its mode, so the derivatives have the jump of the STM at the switching time. The initial mode is the sign of S at t0, or on the surface the mode whose flow leaves it. The inputs and the results are those of the model without modes, except for the results that switch_times adds. A call throws when the flow slides on a surface, or when a mode and its switching function disagree at an output time.
  • switches = nothing: an upper bound on the number of switches between t0 and tf, or between two output times of times; a call throws when more come. modes requires it, and it requires modes: otherwise integrator throws ArgumentError. events counts the events of "zero" only, and needs the exact number.
  • switch_times = false: with true, the results end with the switch times ts (switches of them; a missing switch has the time tf), the index is of the switching function of each with more than one mode, and their number ns. A vector of times does not support it.
  • options...: options of the solver, for example abstol, reltol and maxiters.

With an event function, the function returns the state at the event, the quadratures if the model has them, and the event time te; te is a vector with events more than 1. With several event functions, the result ie follows: for each event, the index from 1 of the event function that changed its sign. With exact = false, the last result ne is the number of events, and a missing event has the time tf and the index 0. A zero at the initial time is not an event.

See Integrate a differential equation and Stop at an event.

CasADiCodegen.Codegen.linearization — Function

CasADiCodegen.Codegen.linearization_function — Function
linearization_function(f, h; sparse = false) -> CasADiCodegen.Function
linearization_function(f, g, h; sparse = false) -> CasADiCodegen.Function

Return the CasADi function (x, u, p) -> (A, B, C, D) of the linearization of the state-space model x' = f(x, u, p), y = h(x, u, p), with A of size nx × nx, B of nx × nu, C of ny × nx and D of ny × nu for x, u and y of the sizes nx, nu and ny:

\[A = ∂f/∂x, \quad B = ∂f/∂u, \quad C = ∂h/∂x, \quad D = ∂h/∂u.\]

f and h are CasADi functions of the column vectors x, u and p, with one column vector as their result; f has the size of x. Give p of no element for a model with no parameter. The matrices are dense; with sparse = true they keep the sparsity patterns of the Jacobians. linearization gives the generated code of this function.

With three functions of (x, z, u, p), the model is the differential-algebraic system x' = f(x, z, u, p), 0 = g(x, z, u, p), y = h(x, z, u, p) with the algebraic states z, and the result is the function (x, z, u, p) -> (A, B, C, D). The algebraic states are eliminated by the implicit function theorem: with M = (∂g/∂z) \ [∂g/∂x ∂g/∂u],

\[[A \; B] = [∂f/∂x \; ∂f/∂u] - (∂f/∂z) M, \quad [C \; D] = [∂h/∂x \; ∂h/∂u] - (∂h/∂z) M.\]

The result of g has the size of z. The matrices are those of the model at a point where g = 0 and ∂g/∂z is invertible, which need not be a steady state. The caller ensures both conditions: they are not checked, and at a point where g ≠ 0 the matrices do not describe the model.

CasADiCodegen.Codegen.reduce_index — Function
reduce_index(dae; baumgarte_pole = 0.0) -> NamedTuple

Reduce the semi-explicit differential-algebraic equation dae to index 1 by differentiating its algebraic equations, with the structural algorithm of Pantelides. Return (; dae, invariants, differentiations, index).

dae is a dictionary in the form of the CasADi integrators, with SX or MX values that are dense column vectors: the differential states "x", the algebraic states "z", the parameters "p", the scalar time "t", and the expressions "ode", the derivative of x, and "alg", the algebraic equations 0 = alg, of the size of z. "x", "z" and "t" are symbols or concatenations of symbols. "p" and "t" are optional, and so are "z" and "alg" together.

The result dae has the same form, and CasADiCodegen.C.integrator with a DAE plugin such as "idas" accepts it. Equation alg[i] is replaced by its time derivative of order differentiations[i], in which the derivative of x is replaced by ode. An algebraic state z[j] whose derivative enters these equations becomes a differential state, and its derivative a new symbol that takes its place in z. The states of the result are x, then for each such z[j], in the order of z, the state and its derivatives below the highest. A derivative is named "d" followed by the name of the symbol. For T differentiated twice, for example, the result has the states [x; T; dT] with the derivative [ode; dT; ddT], and ddT in z. The element k of an MX vector symbol z is first replaced by the scalar symbol z_k, counted from 0, as the elements of an SX vector symbol are named, so a function of the result takes dae["x"] and dae["z"] of the result, not the original symbols.

invariants is the column of the replaced equations and of their derivatives of lower order, by equation and then by order, in the symbols of the result. They are zero along a solution that starts where they are zero, but the reduced equations do not enforce them, so a numerical solution drifts away from them. A consistent initial point satisfies invariants and alg. index is the differentiation index: 0 with no algebraic equation, otherwise 1 plus the largest number of differentiations.

A model of index 1 is returned unchanged, with differentiations all 0 and no invariant. Write a fully implicit equation 0 = F(x', x, z) in this form with new algebraic states w for x', ode = w and alg = F(w, x, z).

Keywords

  • baumgarte_pole = 0.0: the pole γ ≤ 0 of Baumgarte's stabilization. An equation g differentiated k times becomes the sum over j in 0:k of binomial(k, j) (-γ)^j times the derivative of g of order k - j, whose characteristic polynomial (s - γ)^k has the root γ, so that its invariants decay as exp(γ t) instead of drifting. 0 gives the derivative of order k alone, as dae_reduce_index of CasADi does by default. A positive γ throws ArgumentError.

Throws ArgumentError when the equations are structurally singular, that is, when no number of differentiations determines the states; the message names the equations ode[i] and alg[i] that are involved, with i from 1. The algorithm uses the sparsity patterns only, and terms of a derivative can cancel. When the reduced equations then do not determine z, the function throws ArgumentError too; it never returns such a model.

The algorithm does not select dummy derivatives (Mattsson and Söderlind): the reduced model keeps every state and enforces only the highest derivative of each equation, so the invariants drift unless they are stabilized. See Model physical systems with differential-algebraic equations.

CasADiCodegen.Codegen.nan_trace — Function
nan_trace(f, arguments...) -> NamedTuple or nothing

Find where the first NaN appears when the CasADi function f runs on numbers. Return the first instruction of the scalar code of f whose result is NaN while no operand is, or the first NaN among the arguments. Return nothing when there is no NaN.

Give one argument per input: an array with the shape of the input, or the vector of its structural nonzeros. CasADi must be able to expand f to scalar code, so f cannot call a Julia function.

The result has these fields:

  • instruction: the place of the instruction in the scalar code.
  • operation: the operation, for example :OP_SQRT.
  • operands: the values of the operands.
  • result: the result of the operation.
  • text: the operation on those values, or the place of the NaN in the arguments.

Examples

julia> using CasADiCodegen

julia> x = SX.sym("x", 2);

julia> f = CasadiFunction("f", [x], [sqrt(x[1]) + x[2]]);

julia> CasADiCodegen.nan_trace(f, [-1.0, 2.0])
(instruction = 2, operation = :OP_SQRT, operands = (-1.0,), result = NaN, text = "NaNMath.sqrt(-1.0)")

julia> CasADiCodegen.nan_trace(f, [1.0, 2.0]) === nothing
true
