Speed up compilation of large models

A model with tens of thousands of instructions compiles slowly, and Julia compiles it again in each session.

Split a large function into smaller pieces

Above a limit, the generated code is split into sub-functions that share one work vector. Two keywords of build_function and generate_julia control the split:

KeywordMeaningDefault
split_aboveA function with more instructions is split50,000 for scalar code; 1,000 for matrix code
chunk_sizeLargest number of instructions in one sub-function1,000

In matrix code, an instruction is one operation of the MX graph; split_above = typemax(Int) keeps any function in one piece. The split can shorten the first call by a factor of six but makes later calls 15 to 40 percent slower (see Compile and run time of a split function).

Compile at a lower optimization level

For a model that changes often, pass optlevel to compile the returned functions faster:

g, g! = build_function(f; expression = Val{false}, optlevel = 1)
optlevelFirst callLater calls
2 (the default of Julia)0.41 s1.55 µs
10.27 s1.60 µs
00.21 s2.07 µs

The times are those of a two-body model with 258 states on Julia 1.13. generate_julia and cache honor the same keyword.

Keep the compiled code between sessions

With cache, build_function stores the generated code as a precompiled package, so that a later session with the same model compiles nothing:

g, g! = build_function(f; expression = Val{false}, cache = true)
# in another directory
g, g! = build_function(f; expression = Val{false}, cache = "/path/to/cache")
FunctionWithout cache, each sessionWith cache, first sessionWith cache, later sessions
Chain of maps, 22,236 instructions6.2 s16.8 s1.1 s
Chain of maps, 67,236 instructions16.4 s19.7 s1.3 s
Two-body integrator, final state and its Jacobian4.1 s12.8 s2.0 s

Each time includes build_function and the first call. A changed model gets a new package; the packages live in scratchspaces of the first Julia depot and can be deleted at any time.

  • The package is compiled for Float64 on ordinary arrays, plus static arrays with force_SA = true and vectors of nonzeros with nonzeros = true; other argument types compile at their first call.
  • The caller of build_function must call the functions with Base.invokelatest.
  • A Julia function in the graph must be a named function of a package.
  • Structural zeros in an input or output require SparseArrays in the environment.

Keep bounds checks off in tests

--check-bounds=yes makes the first call of a large function compile much longer; Pkg.test sets it on Julia 1.12 but not on 1.13. For fixed-step integrators of CasADi:

First call ofJulia 1.12Julia 1.12, --check-bounds=yesJulia 1.13Julia 1.13, --check-bounds=yes
rk with Jacobians2.6 s23.7 s2.1 s8.3 s
collocation with Jacobians4.3 s41.5 s3.4 s11.5 s
collocation with derivatives of the second order16.6 s533 s14.6 s144 s

On Julia 1.12, run such tests with Pkg.test(...; julia_args = ["--check-bounds=auto"]).
