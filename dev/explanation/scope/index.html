Scope and differences from CasADi

This page lists what the package supports, what it refuses when it builds the code, and where the generated code or the front end behaves differently from CasADi or from Julia. It is meant for a reader who checks whether a model fits the package before writing it, or who meets an error at build time.

What is refused

Generated code never calls CasADi, so a function of CasADi for which the package has no method is refused when the code is built. The message names the function and says what the user can do, as the table below shows.

Differences from CasADi

  • The newton rootfinder does not read the option constraints, because the Newton method of CasADi does not use it. It solves each linear system by elimination with row exchanges, dense or, for a Jacobian of 16 rows or more with at most a quarter of its elements stored, sparse LU in the order of the unknowns, where CasADi uses a QR factorization, so the roots agree to rounding error only.

  • An operation that leaves its domain gives NaN, through NaNMath.jl, as in CasADi; nanmath = false selects the functions of Base, which throw. erfinv is the accurate SpecialFunctions.erfinv, where that of CasADi has a relative error up to 1e-4.

  • Determinant and inverse use a dense LU factorization, where CasADi uses a sparse QR factorization, so the results agree to rounding error only, and a singular matrix gives Inf or NaN and no error. A linear solve does too, except that a solve with a sparse matrix of 8 rows or more uses the sparse QR factorization of CasADi when its factors have fewer nonzeros than half of the full matrix; for a tridiagonal matrix, measured once:

    RowsSparse QRDense LUCasADi virtual machine
    501.9 µs10.3 µs6.6 µs
    2007.8 µs143.7 µs12.3 µs

  • CasADi 3.8.2 computes a wrong value, read from other memory, for one node: the sum into the nonzeros at a fixed slice plus indices that are values of the model. This node is the reverse derivative of a read such as get_nz(v, false, Slice(1, 5, 2), i), in which the Slice of CasADi counts from 0 and so selects the second and the fourth nonzero. The generated code gives the correct sum, so its result differs there from that of the virtual machine of CasADi, the interpreter with which CasADi evaluates a function on numbers.

  • CasADi 3.8.2 misses an event of a cvodes integrator that falls exactly on one of its output times, so the state does not jump there or later. The code that replaces such an integrator (see Integrators with events) applies the event and returns the state after it at that output time, which is the solution of the model; with an event function 10 - t, a jump of 50 and the output times 5, 10, 10.5 and 15, the two results differ by up to 50 after t = 10, while with the event at 10.25 they agree.
