Scope and differences from CasADi

This page lists what the package supports, what it refuses at build time, and where its results differ from those of CasADi.

Functions the package rejects, and what to do instead

Generated code never calls CasADi, so a CasADi function without a method in the package is refused at build time with a message that names the function and the remedy.

Function of CasADi in the graphRemedy
Integrator cvodes or idas, rootfinder kinsol or fast_newton, solver of nlpsol or of conic (quadratic problem, which CasADi does not differentiate either)A SciML solver through the option solvers (see Run CasADi solver objects with SciML solvers)
Integrator rk or collocation with an event functionA solver through Solvers(overrides = ...)
Subtype of Callback (a callback written as a Julia type, whose object CasADi keeps to itself)callback with a Julia function
conic with cone constraints; other classes such as a Functional Mock-up Unit (FMU)None
Matrix 2-norm without expansionNone: CasADi cannot evaluate it either

Where results differ from CasADi

  • The newton rootfinder ignores the option constraints, which the Newton method of CasADi does not use either. It solves each linear system by Gaussian elimination with row exchanges, or by sparse LU for a Jacobian of 16 rows or more with at most a quarter of its elements stored, where CasADi uses QR; the roots agree to rounding error.

  • The elementary functions are those of Julia, where CasADi calls the C library of the platform. On Linux and macOS they agree to the last bits; the C library of Windows rounds sin, cos, tan and pow less closely, and differs from Julia at large arguments (sin(1e300)) and in the leading digits of tiny results (sin(π)). On ARM, the C compiler of CasADi fuses some products and sums into one rounding, so a routine read from its C code, such as kron_contract, can differ in the last bit.

  • CasADi converts a number to an integer, for the index of conditional and the place of an interpolant on an equidistant grid, with a cast of C, whose result for NaN or a value out of range depends on the processor; the generated code follows the processor that runs it.

  • An operation outside its domain gives NaN through NaNMath.jl, as in CasADi; nanmath = false selects the Base functions, which throw. erfinv is SpecialFunctions.erfinv, whereas that of CasADi has a relative error up to 1e-4.

  • Determinant, inverse, and linear solve with a matrix below 8 rows use dense LU where CasADi uses sparse QR, so results agree to rounding error and a singular matrix gives Inf or NaN without an error. A linear solve with a sparse matrix of 8 rows or more uses the sparse QR of CasADi when its factors have fewer nonzeros than half the full matrix; for a tridiagonal matrix, measured once:

    RowsSparse QRDense LUCasADi virtual machine
    501.9 µs10.3 µs6.6 µs
    2007.8 µs143.7 µs12.3 µs

  • CasADi 3.8.2 returns a wrong value, read from other memory, for the sum into nonzeros at a fixed slice plus computed indices, the reverse derivative of a read such as get_nz(v, false, Slice(1, 5, 2), i); the generated code gives the correct sum.

  • CasADi 3.8.2 misses a cvodes event that falls on an output time, so the state does not jump there or later. The replacing code (see Replace an integrator that has events) applies the event and returns the state after it at that output time.
