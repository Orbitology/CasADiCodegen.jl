Scope and differences from CasADi

This page lists what the package supports, what it refuses at build time, and where its results differ from those of CasADi.

What is supported

ItemState
Scalar (SX) functionsEvery scalar operation of CasADi 3.8.2 (below)
Matrix (MX) functions, not expandedElementwise operations, slices, joins, splits, transpose, reshape, projection (change of sparsity pattern), assignment to chosen nonzeros, reads at computed indices, interval search in a grid, monitor, calls of SX and MX functions, map, mapaccum, fold; if_else and conditional with short_circuit = true run only the selected branch
Functions and nodes of CasADi without instructionsInterpolants linear and bspline, the B-spline node, einstein, kron_contract, repsum, convexify, attachAssert, printme, dump, lift, find, map (serial, threads or OpenMP) as one loop, external functions (Float64 only), rootfinder newton, integrators rk and collocation with first- and second-order sensitivities

In generated code through solvers = CasADiCodegen.Solvers(...): cvodes, idas, kinsol, fast_newton with forward and reverse derivatives; nlpsol solvers, Float64 only, forward and reverse; integrators with event functions, also with algebraic states, Float64 only, forward only; conic solvers of quadratic problems

What is refused

Generated code never calls CasADi, so a CasADi function without a method in the package is refused at build time with a message that names the function and the remedy.

Function of CasADi in the graphRemedy
Integrator cvodes or idasA SciML solver through the option solvers (see Replace the solvers of CasADi)
Rootfinder kinsol or fast_newtonA solver through solvers
Solver of nlpsolA solver through solvers
Integrator rk or collocation with an event functionA solver through Solvers(overrides = ...)
Subtype of Callback (a callback written as a Julia type, whose object CasADi keeps to itself)callback with a Julia function
Solver of conic (quadratic problem)A solver through solvers, field optimization; CasADi has no derivatives of it either
conic with cone constraints; other classes such as a Functional Mock-up Unit (FMU)None
Matrix 2-norm without expansionNone: CasADi cannot evaluate it either

Differences from CasADi

  • The newton rootfinder ignores the option constraints, which the Newton method of CasADi does not use either. It solves each linear system by Gaussian elimination with row exchanges, or by sparse LU for a Jacobian of 16 rows or more with at most a quarter of its elements stored, where CasADi uses QR; the roots agree to rounding error.

  • An operation outside its domain gives NaN through NaNMath.jl, as in CasADi; nanmath = false selects the Base functions, which throw. erfinv is SpecialFunctions.erfinv, whereas that of CasADi has a relative error up to 1e-4.

  • Determinant, inverse and linear solve use dense LU where CasADi uses sparse QR, so results agree to rounding error and a singular matrix gives Inf or NaN without an error. A linear solve with a sparse matrix of 8 rows or more uses the sparse QR of CasADi when its factors have fewer nonzeros than half the full matrix; for a tridiagonal matrix, measured once:

    RowsSparse QRDense LUCasADi virtual machine
    501.9 µs10.3 µs6.6 µs
    2007.8 µs143.7 µs12.3 µs

  • CasADi 3.8.2 returns a wrong value, read from other memory, for the sum into nonzeros at a fixed slice plus computed indices, the reverse derivative of a read such as get_nz(v, false, Slice(1, 5, 2), i); the generated code gives the correct sum.

  • CasADi 3.8.2 misses a cvodes event that falls on an output time, so the state does not jump there or later. The replacing code (see Integrators with events) applies the event and returns the state after it at that output time.
