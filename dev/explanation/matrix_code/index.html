Scalar code, matrix code and special CasADi functions

The package generates two kinds of code from a matrix (MX) function, expanded scalar code and matrix code. It also translates the special functions that CasADi runs as its own compiled code, such as interpolants, integrators and rootfinders, so that the generated code never calls CasADi.

Expand to scalar code or keep matrix operations

The default expand = true expands an MX function to scalar operations. This gives the fastest code for a model of moderate size, but repeats the body of a called function at each call (see Compile and run time of scalar and matrix code). When the repetition would give more than 20000 scalar operations and more than 10 times the operations of the functions involved, each counted once, the function keeps its matrix operations: an integrator or a fold of 1000 steps calls its step rather than writing it 1000 times. A map counts as its copies, since the code does that work anyway, so it is still expanded.

With expand = false the code keeps the matrix operations, compiles each called function once, and shares the code of functions with the same content. A function that calls no other function and has more argument nonzeros (stored entries of its arguments) than operations, such as an inline interpolant with its table as an argument, is inlined.

g, g! = build_function(f; expression = Val{false}, expand = false)   # f is an MX function

Matrix code reads constants, and arguments of an unsplit function, without a copy, so a table lookup costs the same for any table size. When a function calls Julia functions at its top level, expand = true expands the operations between the calls (see Call a Julia function from the model); the code keeps the matrix operations only when CasADi cannot expand those parts, or when a called function calls a Julia function.

Expanded code computes every branch of if_else and conditional, even with short_circuit = true, so an expensive branch needs expand = false. A branch that CasADi cannot expand, such as a call of a Julia function, gives matrix code with either setting.

How matrix code writes `map`, `mapaccum` and `fold`

Matrix code writes a map, and a strided copy of nonzeros as in a transpose, as one loop over blocks. The nested functions of mapaccum and fold give code that grows with the logarithm of the number of steps, where expanded code repeats the body for each column or step.

How interpolants and other special functions become Julia code

CasADi does not expose the data of these functions through its interface. The package reads it from the C code that CasADi generates (tables, index lists) and from the output of serialize (solver options), and emits Julia code that accepts dual numbers. At build time it compares the results with those of CasADi at fixed test points; a difference is an error, although agreement there does not prove agreement at every input.

Run time compared with CasADi

One call with Float64, measured once, against the CasADi virtual machine (its interpreter on numbers). The interpolants have 9 points and return the value with its derivative; the integrators have 2 states and 20 steps and return the final state with its Jacobian; the rootfinder has 2 unknowns and returns the root with its Jacobian by 3 parameters:
