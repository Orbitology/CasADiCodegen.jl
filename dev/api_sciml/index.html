SciML problems and functions

The methods of this page exist once SciMLBase.jl is loaded, which each SciML solver package does, and the bifurcation problem once BifurcationKit.jl is loaded too. Their names follow the conventions of the API reference.

SciML problems from solvers and models of CasADi

These constructors make a SciML problem from a solver object of CasADi, from a DaeBuilder or from an Opti, with generated code for the model and its derivatives.

SciMLBase.ODEProblem — Method
SciMLBase.ODEProblem(I::CasADiCodegen.Function, x0, p = Float64[]; z0 = Float64[], u = Float64[],
                     specialize = SciMLBase.FullSpecialize, options...)

Make the SciML problem of the integrator I of CasADi (cvodes, idas, rk or collocation), with generated code for its right side and for the Jacobians of it.

  • The state has the differential states from x0, then the algebraic states from z0, then the quadratures, which start at zero. z0 must satisfy the algebraic equations at the initial time: the default initialization of the SciML solvers checks it and stops.
  • The parameters are p and then the controls of the current interval. u has one block of controls per output time of I, as for the integrators of CasADi: block k holds from output time k - 1, or from the initial time, to output time k. With more than one block the problem has a callback that changes the controls at each output time.
  • The time span is from the initial time of I to its last output time. The output times are the option saveat, so the solution has one state per output time of I.
  • The tolerances of cvodes and of idas are the options abstol and reltol.
  • With algebraic states the problem has a mass matrix, so it needs a solver for such problems, for example Rodas5P() of OrdinaryDiffEqRosenbrock.jl.
  • specialize is the specialization of the function of the problem. With SciMLBase.AutoSpecialize, the problems of several integrators with the same kind of mass matrix and callback share one compiled solver.

The other options go to the problem, and replace these ones.

An event function gives a callback: when one of its values changes its sign from positive to negative, the state becomes that of the option transition of I. The vectors must have the sizes of I. A callback among the options runs after the one that changes the controls and after that of the events. The callback writes the controls into the parameters of the problem, so do not solve one problem with several intervals from two tasks at the same time. See Replace the solvers of CasADi.

Examples

problem = SciMLBase.ODEProblem(I, [1.0, 0.0, 0.0, 1.0], [1.0])      # I is a `cvodes` integrator
solution = SciMLBase.solve(problem, Vern9(); abstol = 1e-13, reltol = 1e-13)

SciMLBase.ODEProblem — Method
SciMLBase.ODEProblem(dae::CasADiCodegen.C.DaeBuilder, tspan = nothing; jac = true, paramjac = true,
                     sparse = false, specialize = SciMLBase.FullSpecialize, chunk_size = nothing,
                     split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML problem of the model dae of CasADi, with generated code for its right side and for the Jacobians of it, and with the start values of its variables.

  • The state has the differential states x, then the algebraic states z of dae. The initial state is their start values. The algebraic start values must satisfy the algebraic equations, as for ODEProblem(I; z0) of an integrator.
  • The parameters are p, then the inputs u, from their start values. The inputs are constant over the solve.
  • The time span is tspan, or the start and stop times of dae when tspan is nothing.
  • With algebraic states the problem has a mass matrix, so it needs a solver for such problems, for example Rodas5P() of OrdinaryDiffEqRosenbrock.jl.
  • When each variable is a scalar, the problem has the names of the variables, so that solution[:x] gives the values of the variable x.

The dependent variables w and the constants c of dae are substituted into the equations; CasADi takes the value of a constant from set(dae, name, value), not from its start value. A model with quadratures q or with when equations is not supported. The keywords from jac to cache go to ODEFunction; the other options go to the problem.

Examples

dae = CasADiCodegen.C.DaeBuilder("decay")
x, k = CasADiCodegen.C.add(dae, "x", "local", "continuous"), CasADiCodegen.C.add(dae, "k", "parameter", "tunable")
CasADiCodegen.C.eq(dae, CasADiCodegen.C.der(dae, x), -k * x)
CasADiCodegen.C.set_start(dae, "x", 1.0)
CasADiCodegen.C.set_start(dae, "k", 0.5)
solution = SciMLBase.solve(SciMLBase.ODEProblem(dae, (0.0, 2.0)), Vern9())
solution[:x]

SciMLBase.NonlinearProblem — Method
SciMLBase.NonlinearProblem(R::CasADiCodegen.Function, z0, others...; options...)

Make the SciML problem of the rootfinder R of CasADi (newton, fast_newton or kinsol), with generated code for the residual and for its Jacobian.

z0 is the first guess of the unknown. others are the other arguments of R, in their order, as vectors of their nonzeros; the parameters of the problem are those vectors, joined. The vectors must have the sizes of R. The options go to the problem.

Examples

problem = SciMLBase.NonlinearProblem(R, [1.0], [1.0, 0.3])          # R(z0, p) is a `kinsol` rootfinder
solution = SciMLBase.solve(problem, SimpleNewtonRaphson())

SciMLBase.SDEProblem — Method
SciMLBase.SDEProblem(f::CasADiCodegen.Function, g::CasADiCodegen.Function, u0, tspan, p = SciMLBase.NullParameters();
                     jac = true, paramjac = true, sparse = false, inplace = true,
                     specialize = SciMLBase.FullSpecialize, chunk_size = nothing, split_above = nothing,
                     optlevel = nothing, cache = false, options...)

Make the SciML problem of the stochastic differential equation with the drift f and the noise g from the initial state u0 over tspan. The function of the problem is SDEFunction(f, g) with the keywords before options, which go to SciMLBase.SDEProblem.

For a noise matrix, the problem has a noise_rate_prototype of zeros of the size of g: a Matrix, with sparse = true a SparseMatrixCSC of the sparsity pattern of g, and with inplace = false an SMatrix. An option noise_rate_prototype replaces it.

Examples

using CasADiCodegen
import SciMLBase
using StochasticDiffEqLowOrder: LambaEM

x = SX.sym("x", 2)
drift = CasadiFunction("drift", [x], [-x])
noise = CasadiFunction("noise", [x], [[0.1 * x[1] 0.0 0.2; 0.0 0.3 * x[2] 0.2]])   # three Wiener processes
problem = SciMLBase.SDEProblem(drift, noise, [1.0, 1.0], (0.0, 1.0))
solution = SciMLBase.solve(problem, LambaEM(); seed = 1)

SciMLBase.OptimizationProblem — Method
SciMLBase.OptimizationProblem(S::CasADiCodegen.Function, x0, p = Float64[]; lbx, ubx, lbg, ubg,
                              hess = true, sparse = false, lag_h = sparse && hess, chunk_size = nothing,
                              split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML problem of the solver S that nlpsol or conic of CasADi made, with generated code for the objective, the constraints and their derivatives. The keywords from hess to cache have the meaning that they have for OptimizationFunction.

For a solver of conic, the parameters p are the nonzeros of h, then g, then the nonzeros of a, and the constraints g of the bounds are the rows of a.

The bounds have the names and the default values of CasADi: no bound on the unknowns, and none on the constraints. The other options go to the problem. The unknowns must be a column vector, and the vectors must have the sizes of S.

SciMLBase.OptimizationProblem — Method
SciMLBase.OptimizationProblem(opti::CasADiCodegen.C.Opti; hess = true, sparse = false, lag_h = sparse && hess,
                              chunk_size = nothing, split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML problem of the optimization problem that the Opti object of CasADi holds, with generated code for the objective, the constraints and their derivatives.

  • The unknowns are the variables of opti, in the order of their declaration, as C.x(opti) joins them. Their initial values come from set_initial, or are zero.
  • The parameters are the parameters of opti (C.p(opti)), with the values from set_value. Each parameter must have a value.
  • The constraints are those of subject_to, with the bounds that opti gives them. opti keeps a bound on a variable as a constraint, so the problem has no lb and ub. A bound that depends on a parameter has the value of this call; a later change of the parameters in the problem does not change it.

The keywords from hess to cache have the meaning that they have for OptimizationFunction. The other options go to the problem. C.value(opti, expression, [C.x(opti) == CasADiCodegen.DM(solution.u)]) evaluates an expression of opti at the solution.

Examples

C = CasADiCodegen.C
opti = C.Opti()
x, a = C.variable(opti, 2), C.parameter(opti)
C.minimize(opti, (x[1] - a)^2 + x[2]^2)
C.subject_to(opti, x[1] + x[2] >= 1)
C.set_value(opti, a, C.DM(0.25))
problem = SciMLBase.OptimizationProblem(opti; sparse = true)
solution = SciMLBase.solve(problem, OptimizationIpopt.IpoptOptimizer())

Functions of SciML problems

SciMLBase.ODEFunction — Method
SciMLBase.ODEFunction(f::CasADiCodegen.Function; jac = true, paramjac = true, sparse = false,
                      inplace = true, specialize = SciMLBase.FullSpecialize, chunk_size = nothing,
                      split_above = nothing, optlevel = nothing, cache = false, initialization = nothing,
                      solved_parameters = Symbol[], options...)

Make the SciML function of the ordinary differential equation whose right side is the CasADi function f(u), f(u, p) or f(u, p, t). It holds generated code for the right side and for its Jacobians by the state (jac) and by the parameters (paramjac).

The first result of f is the right side, a column vector of the size of its first argument. Each further result, a column vector, is an observed variable. Set jac or paramjac to false to leave that Jacobian out.

The function has the names of the symbols of f as its sys, so that solution[:x], remake(problem; p = [:k => 2.0]), problem.ps[:k] and the observed function SymbolicIndexingInterface.observed(problem, :x) of a state, a parameter or a further result work:

  • The states, the parameters and the time have the names of the scalar symbols of the arguments of f. The elements of one symbol of several elements, such as MX.sym("x", 2), are x_0 and x_1, as CasADi names the elements of SX.sym("x", 2). A parameter symbol of several elements is also one parameter by its own name, so that remake(problem; p = [:x => [1.0, 2.0]]) replaces all its elements. Without a third argument the time is t.

A function of the time without parameters takes an empty parameter argument, such as SX(0, 1); its problem then needs no parameters.

  • An observed variable has the name of its result (see C.name_out). A result of more than one element y also gives y_0, y_1, ..., one per element.

A function whose arguments are not made of named symbols, or whose names occur twice, gets no names, and then a further result throws an ArgumentError. A sys among the options replaces the names and the observed variables. With sparse = true the function has a jac_prototype: a SparseMatrixCSC with the sparsity pattern of the Jacobian, into whose stored values jac writes. It needs SparseArrays.jl loaded and jac = true. Besides the in-place jac(J, u, p, t), the Jacobians have the out-of-place method jac(u, p, t), which returns a new matrix: dense, or with sparse = true a sparse matrix of the pattern of jac_prototype.

With inplace = false the functions are out of place and return static arrays: an SVector for the right side and an SMatrix for each Jacobian, also of one row or one column. Use it with an SVector state. Each of these arrays holds at most 1024 elements, so jac = true allows at most 32 states; a larger function throws an ArgumentError. specialize is the specialization of the SciML function: SciMLBase.AutoSpecialize lets OrdinaryDiffEq.jl wrap the in-place functions of a Vector{Float64} state, so that the solver code compiled for one model serves the next one; an explicit solver wraps them only with jac = false. chunk_size, split_above, optlevel and cache go to build_function.

initialization is a CasADi function with the arguments of f whose first result, a column vector, holds conditions c(u, p, t) = 0 on the initial values. With it the function has an initialization_data, from which the default initializealg of OrdinaryDiffEq.jl solves the algebraic equations of f and the conditions together before the first step. The algebraic equations are the rows of zeros of the option mass_matrix. The unknowns are the state, whose values in the problem are a guess, and the parameters in solved_parameters, given by name or by place. The initialization problem is a NonlinearProblem when it has as many equations as unknowns, and a NonlinearLeastSquaresProblem otherwise; see initialization_problem. A condition on a derivative calls f on the arguments of initialization. With specialize = SciMLBase.AutoSpecialize, functions of one f with other conditions have one type, so that the solvers compiled for the first serve the others.

The default nonlinear solver of OrdinaryDiffEq.jl needs OrdinaryDiffEqNonlinearSolve.jl loaded, and starts with Broyden's method, which does not use the generated Jacobian and can leave the guess for another solution. A method that uses it is given as initializealg = SciMLBase.OverrideInit(; nlsolve = TrustRegion()), to solve or to the problem.

The other options go to SciMLBase.ODEFunction. See Give a CasADi function to a SciML problem.

Examples

using CasADiCodegen
import SciMLBase

x, v, k, t = SX.sym("x"), SX.sym("v"), SX.sym("k"), SX.sym("t")
rhs = CasadiFunction("rhs", [vcat(x, v), k, t], [vcat(v, -k * x), (v^2 + k * x^2) / 2],
                     ["u", "k", "t"], ["du", "energy"])
problem = SciMLBase.ODEProblem(SciMLBase.ODEFunction(rhs), [1.0, 0.0], (0.0, pi), [4.0])
# After `solution = solve(problem, Tsit5())`: solution[:x], solution[:energy]
source
SciMLBase.SDEFunction — Method
SciMLBase.SDEFunction(f::CasADiCodegen.Function, g::CasADiCodegen.Function; jac = true, paramjac = true,
                      sparse = false, inplace = true, specialize = SciMLBase.FullSpecialize,
                      chunk_size = nothing, split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of the stochastic differential equation du = f(u, p, t) dt + g(u, p, t) dW from the CasADi functions f of the drift and g of the noise. It holds generated code for the drift, the noise and the Jacobians of the drift.

f is as for ODEFunction, and the keywords have the meaning that they have there; its further results are observed variables. g has the arguments of f and one result with a row per state:

  • a column vector gives diagonal noise, with one Wiener process per state, or scalar noise, with one Wiener process for all, when the problem has a scalar Wiener process as its option noise, such as WienerProcess(0.0, 0.0, 0.0) of DiffEqNoiseProcess.jl, whose third value starts the auxiliary process that methods of high order such as SRIW1 need;
  • a matrix gives non-diagonal noise, with one Wiener process per column. The problem needs the option noise_rate_prototype, a matrix of the size of g, which SDEProblem makes.

The noise g(out, u, p, t) writes a dense matrix or a SparseMatrixCSC of any pattern, which then takes the sparsity pattern of g. Its out-of-place method g(u, p, t) returns a new vector or matrix. With inplace = false the noise returns an SVector or an SMatrix.

Examples

using CasADiCodegen
import SciMLBase

x, mu, sigma, t = SX.sym("x"), SX.sym("mu"), SX.sym("sigma"), SX.sym("t")
drift = CasadiFunction("drift", [x, vcat(mu, sigma), t], [mu * x])
noise = CasadiFunction("noise", [x, vcat(mu, sigma), t], [sigma * x])
f = SciMLBase.SDEFunction(drift, noise)          # geometric Brownian motion
source
SciMLBase.DiscreteFunction — Method
SciMLBase.DiscreteFunction(f::CasADiCodegen.Function; inplace = true, specialize = SciMLBase.FullSpecialize,
                           chunk_size = nothing, split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of the map u⁺ = f(u, p, t) of a discrete-time system from the CasADi function f(u), f(u, p) or f(u, p, t). It holds generated code for the map.

The first result of f is the next state, a column vector of the size of its first argument. The solver FunctionMap of OrdinaryDiffEqFunctionMap.jl calls the map with the time of the next state, t + dt. Each further result, a column vector, is an observed variable, which a solution computes from each saved state at the time of that state. The states, the parameters, the time and the observed variables have names as for ODEFunction, and the keywords have the meaning that they have there. With inplace = false the map returns an SVector. The other options go to SciMLBase.DiscreteFunction.

Examples

using CasADiCodegen
import SciMLBase

using OrdinaryDiffEqFunctionMap: FunctionMap

x, r = SX.sym("x"), SX.sym("r")
logistic = CasadiFunction("logistic", [x, r], [r * x * (1 - x)])
problem = SciMLBase.DiscreteProblem(SciMLBase.DiscreteFunction(logistic), [0.2], (0.0, 50.0), [3.2])
solution = SciMLBase.solve(problem, FunctionMap())
solution[:x]

SciMLBase.ImplicitDiscreteFunction — Method
SciMLBase.ImplicitDiscreteFunction(f::CasADiCodegen.Function; inplace = true,
                                   specialize = SciMLBase.FullSpecialize, chunk_size = nothing,
                                   split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of the implicit map 0 = f(u⁺, u, p, t) of a discrete-time system from the CasADi function f(u⁺, u), f(u⁺, u, p) or f(u⁺, u, p, t). It holds generated code for the residual.

The first two arguments are the next and the current state, column vectors of one size. The one result, a column vector, is the residual. The solver IDSolve of ImplicitDiscreteSolve.jl solves f(u⁺, u, p, t + dt) = 0 for u⁺ at each step; its nonlinear solver differentiates the residual with dual numbers, since a SciMLBase.ImplicitDiscreteFunction holds no Jacobian. A residual of more elements than the state gives the function a resid_prototype of zeros of its size, and the step is then a least-squares problem.

By default IDSolve takes the initial state u0 of the problem as the state before the first time: it solves f(u, u0, p, t0) = 0 and starts from u. With initializealg = SciMLBase.NoInit() it starts from u0, whose algebraic elements must then satisfy their equations. IDSolve adapts its steps to the convergence of the nonlinear solver unless it receives adaptive = false and a dt.

The states have the names of the elements of u⁺, and the parameters and the time those of p and t, as for ODEFunction, whose keywords have the same meaning here. With inplace = false the residual returns an SVector; IDSolve does not take that form, since it writes the state in place. The other options go to SciMLBase.ImplicitDiscreteFunction.

source
SciMLBase.NonlinearFunction — Method
SciMLBase.NonlinearFunction(f::CasADiCodegen.Function; jac = true, sparse = false, inplace = true,
                            specialize = SciMLBase.FullSpecialize, chunk_size = nothing,
                            split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of the equations f(u) = 0 or f(u, p) = 0, where f is a CasADi function. It holds generated code for the residual and for its Jacobian (jac).

The first result of f is the residual, a column vector; each further result is an observed variable. A residual of another size than the first argument of f gives the function a resid_prototype of zeros of that size, for a SciMLBase.NonlinearLeastSquaresProblem. Set jac = false to leave the Jacobian out. The names, the keywords sparse, inplace, specialize and those of the code have the meaning that they have for ODEFunction, without the time; in place, the Jacobian also has the out-of-place method jac(u, p). The other options go to SciMLBase.NonlinearFunction.

Examples

residual = CasADiCodegen.Function("r", [z, q], [equations])
problem = SciMLBase.NonlinearProblem(SciMLBase.NonlinearFunction(residual), z0, q0)

SciMLBase.OptimizationFunction — Method
SciMLBase.OptimizationFunction(objective::CasADiCodegen.Function, constraints = nothing; hess = true,
                               sparse = false, lag_h = sparse && hess, chunk_size = nothing,
                               split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of an optimization problem from the CasADi functions objective(x) or objective(x, p) and, if the problem has them, constraints with the same arguments.

The result holds generated code for the objective, its gradient (grad) and its Hessian (hess). With constraints it also holds cons, their Jacobian cons_j, and, unless lag_h, cons_h(H, x, p), where H has one matrix per constraint. hess = false leaves out the derivatives of the second order, for a solver that uses first derivatives only; their code can take long to build.

Each of grad, hess, cons, cons_j and cons_h is in place, as hess(H, x, p), and also has the out-of-place method hess(x, p), which returns a new array. Optimization.jl calls these functions and differentiates nothing, also for a solver that needs the second derivatives.

The matrices are dense unless sparse = true. Then hess, cons_j and cons_h write the stored values of a SparseMatrixCSC with the sparsity pattern of CasADi, which the result holds as hess_prototype, cons_jac_prototype and cons_hess_prototype; options must not hold a prototype then. It needs SparseArrays.jl loaded.

lag_h = true needs sparse = true and hess = true. It adds the Hessian of the Lagrange function σ f + μ' g, as lag_h(h, x, σ, μ, p), in place of cons_h: h receives the stored values of its upper triangle, whose pattern is lag_hess_prototype. Ipopt, through OptimizationIpopt.jl, then makes one call per iteration in place of one Hessian per constraint.

chunk_size, split_above, optlevel and cache go to build_function. The other options go to SciMLBase.OptimizationFunction. x must be a column vector, and the objective one number. The constraints must be a column vector.

Examples

using SparseArrays

x = SX.sym("x", 2)
objective = CasADiCodegen.Function("cost", [x], [(x[1] - 1)^2 + x[2]^2])
constraints = CasADiCodegen.Function("cons", [x], [x[1] + x[2]])
f = SciMLBase.OptimizationFunction(objective, constraints; sparse = true)
problem = SciMLBase.OptimizationProblem(f, [0.0, 0.0]; lcons = [1.0], ucons = [1.0])

CasADiCodegen.Codegen.natural_continuation — Method
CasADiCodegen.natural_continuation(problem::SciMLBase.AbstractNonlinearProblem, alg, values; parameter, halvings = 3, options...) -> Vector{Pair{Float64,<:SciMLBase.NonlinearSolution}}

Solve problem with alg for each value of one parameter in values, in order, each solve starting from the solution of the one before. This is natural continuation, as for the width of a smoothed switch falling toward zero. The method exists once SciMLBase.jl is loaded.

parameter is an Integer, the place of the parameter in problem.p, a vector, or a Symbol or a String, the name of a parameter of the problem. A problem whose function is the NonlinearFunction of a CasADi function f(u, p) names each parameter after its scalar symbol in p. The first solve starts from problem.u0. options go to solve.

When a solve fails, values between the last solved one and the failed one are tried first: the geometric mean when both are positive, else the arithmetic mean, at most halvings times for each value of values. Before the first value, the value of the parameter in problem, with problem.u0, stands for the last one solved. A solve fails when its return code is not successful, or when the solve throws AssertionError (a failed check of generated code), DomainError or LinearAlgebra.SingularException; other errors propagate.

Return one pair value => solution for each value solved, intermediate ones included. The sequence stops at the first value that fails after its halvings tries. Its pair is the last one, with the return code of the solve, or ReturnCode.Failure for an error; so SciMLBase.successful_retcode(last(path).second) tells whether it reached the last value. For a path with turning points, use the extension for BifurcationKit.jl.

Throws ArgumentError for empty or nonfinite values, a negative halvings, a place outside problem.p or with parameters that are not a vector, an unknown name, and a parameter of another type.

Examples

using CasADiCodegen
using SimpleNonlinearSolve: SimpleNewtonRaphson
import SciMLBase

z, width = MX.sym("z"), MX.sym("width")
residual = CasadiFunction("residual", [z, width], [z - 3 + CasADiCodegen.smooth_sign(z - 1, width)])
problem = SciMLBase.NonlinearProblem(SciMLBase.NonlinearFunction(residual), [0.0], [1.0])
path = CasADiCodegen.natural_continuation(problem, SimpleNewtonRaphson(), [0.1, 0.01, 1e-3]; parameter = :width)
root = last(path).second.u                                  # near [2.0]

Bifurcation problems

BifurcationKit.BifurcationProblem — Method
BifurcationKit.BifurcationProblem(f::CasADiCodegen.Function, u0, p, parameter;
                                  record_from_solution = nothing, jac = true, jet = true,
                                  chunk_size = nothing, split_above = nothing,
                                  optlevel = nothing, cache = false, options...)

Make the bifurcation problem of the steady states f(u, p) = 0 of the CasADi function f, continued in the parameter parameter. It holds generated code for the residual, its Jacobian (jac) and, with jet, the higher derivatives that BifurcationKit.jl uses.

f takes the state and the parameters, and its first result is the residual, a column vector of the size of the state. f(u, p, t) with a residual that does not depend on t, such as the right side of an ODEFunction, also serves. The states and the parameters have the names of the scalar symbols of f, as for SciMLBase.NonlinearFunction. Further results of f are observed variables, each known by the name of its result.

u0, the guess of a steady state, and p, the values of the parameters, are vectors in the order of the symbols of f, or vectors of pairs name => value, which must give a value to each element. parameter is the name of a scalar parameter, such as :μ, or its place in p, from 1.

record_from_solution gives what the branch records at each point: a name, or a vector or tuple of names, of states, parameters and observed variables, recorded as a named tuple; a function (u, p; k...) -> value; or nothing for the default of BifurcationKit.jl, the norm of the state.

jac = false leaves the Jacobian to automatic differentiation by BifurcationKit.jl. jet adds the Jacobian-vector product (jvp), the derivatives of the second and the third order by the state in given directions (d2F, d3F), and the derivatives by the continued parameter (R01, R11), which the normal forms at branch points and Hopf points need; with jet = false, BifurcationKit.jl computes them by automatic differentiation of the generated residual, and R11 by finite differences. chunk_size, split_above, optlevel and cache go to build_function, and the other options to BifurcationKit.BifurcationProblem.

Examples

x, μ = SX.sym("x"), SX.sym("μ")
f = CasadiFunction("f", [x, μ], [μ * x - x^3])
problem = BifurcationKit.BifurcationProblem(f, [:x => 0.0], [:μ => -1.0], :μ; record_from_solution = :x)
