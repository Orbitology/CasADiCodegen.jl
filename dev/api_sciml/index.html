SciML problems and functions

The methods on this page exist once SciMLBase.jl is loaded, which every SciML solver package does. The bifurcation problem also needs BifurcationKit.jl. Names follow the conventions of the API reference.

Make a SciML problem from a CasADi model or solver

These constructors make a SciML problem, with generated code for the model and its derivatives, from a CasADi function or solver object, a DaeBuilder, a CasADiCodegen.Models.System or an Opti.

SciMLBase.ODEProblem — Method
SciMLBase.ODEProblem(I::CasADiCodegen.Function, x0, p = Float64[]; z0 = Float64[], u = Float64[],
                     specialize = SciMLBase.FullSpecialize, options...)

Make the SciML problem of the CasADi integrator I (cvodes, idas, rk or collocation), with generated code for its right side and its Jacobians.

  • The state has the differential states from x0, then the algebraic states from z0, then the quadratures, which start at zero. z0 must satisfy the algebraic equations at the initial time: the default initialization of the SciML solvers checks it and stops.
  • The parameters are p and then the controls of the current interval. u has one block of controls per output time of I, as for CasADi's integrators: block k holds from output time k - 1, or from the initial time, to output time k. With more than one block the problem has a callback that changes the controls at each output time.
  • The time span is from the initial time of I to its last output time. The output times are the option saveat, so the solution has one state per output time of I.
  • The tolerances of cvodes and of idas are the options abstol and reltol.
  • With algebraic states the problem has a mass matrix, so it needs a solver for such problems, for example Rodas5P() of OrdinaryDiffEqRosenbrock.jl.
  • specialize is the specialization of the function of the problem. With SciMLBase.AutoSpecialize, the problems of several integrators with the same kind of mass matrix and callback share one compiled solver.

The other options go to the problem, and replace these ones.

An event function gives a callback: when one of its values changes its sign from positive to negative, the state becomes that of the option transition of I. The vectors must have the sizes of I. A callback among the options runs after the one that changes the controls and after that of the events. The callback writes the controls into the parameters of the problem, so do not solve one problem with several intervals from two tasks at the same time. See Run CasADi solver objects with SciML solvers.

Examples

x0 = [1.0, 0.0, 0.0, 1.0]
p = [1.0]
problem = SciMLBase.ODEProblem(I, x0, p)      # I is a `cvodes` integrator
solution = SciMLBase.solve(problem, Vern9(); abstol = 1e-13, reltol = 1e-13)

SciMLBase.ODEProblem — Method
SciMLBase.ODEProblem(dae::casadi.DaeBuilder, tspan = nothing; jac = true, paramjac = true,
                     sparse = false, specialize = SciMLBase.FullSpecialize, chunk_size = nothing,
                     split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML problem of the CasADi model dae, with generated code for its right side and its Jacobians, and with the start values of its variables.

  • The state has the differential states x, then the algebraic states z of dae. The initial state is their start values. The algebraic start values must satisfy the algebraic equations, as for ODEProblem(I; z0) of an integrator.
  • The parameters are p, then the inputs u, from their start values. The inputs are constant over the solve.
  • The time span is tspan, or the start and stop times of dae when tspan is nothing.
  • With algebraic states the problem has a mass matrix, so it needs a solver for such problems, for example Rodas5P() of OrdinaryDiffEqRosenbrock.jl.
  • When each variable is a scalar, the problem has the names of the variables, so that solution[:x] gives the values of the variable x.

The dependent variables w and the constants c of dae are substituted into the equations; CasADi takes the value of a constant from set(dae, name, value), not from its start value. A model with quadratures q or with when equations is not supported. The keywords from jac to cache go to ODEFunction; the other options go to the problem.

Examples

dae = casadi.DaeBuilder("decay")
x = casadi.add(dae, "x", "local", "continuous")
k = casadi.add(dae, "k", "parameter", "tunable")
casadi.eq(dae, casadi.der(dae, x), -k * x)
casadi.set_start(dae, "x", 1.0)
casadi.set_start(dae, "k", 0.5)
tspan = (0.0, 2.0)
problem = SciMLBase.ODEProblem(dae, tspan)
solution = SciMLBase.solve(problem, Vern9())
solution[:x]

SciMLBase.ODEProblem — Method
SciMLBase.ODEProblem(sys::CasADiCodegen.Models.System, u0, tspan, p = Pair[]; jac = true,
                     paramjac = true, sparse = false, specialize = SciMLBase.FullSpecialize,
                     chunk_size = nothing, split_above = nothing, optlevel = nothing,
                     cache = false, options...)

Make the SciML problem of the compiled model sys, with generated code for its right side and its Jacobians.

  • u0 gives the initial values of the states, unknowns(sys): a vector in their order, or pairs from a state to its value, where the state is its symbol, such as D(x), or its name as a Symbol or a String. Each differential state needs a value. An algebraic state without one starts from 0, which a solver must correct, for example with initializealg = BrownFullBasicInit() of OrdinaryDiffEqNonlinearSolve.jl.
  • p gives the values of the parameters in the same ways, each one required.
  • With algebraic states the problem has a mass matrix, so it needs a solver for such problems, for example Rodas5P() of OrdinaryDiffEqRosenbrock.jl.
  • The problem has the names of the states, the parameters and the time, and the observed variables of sys by name, so that solution[:y] gives the values of y.

The keywords from jac to cache go to ODEFunction; the other options go to the problem.

Examples

using CasADiCodegen, CasADiCodegen.Models
t = SX.sym("t")
x = SX.sym("x")
k = SX.sym("k")
D = Differential(t)
sys = System([D(D(x)) ~ -k * x], t; parameters = [k])
u0 = [x => 1.0, D(x) => 0.0]
tspan = (0.0, 1.0)
p = [k => 4.0]
problem = SciMLBase.ODEProblem(sys, u0, tspan, p)

Make the SciML problem of the CasADi rootfinder R (newton, fast_newton or kinsol), with generated code for the residual and its Jacobian.

z0 is the first guess of the unknown. others are the other arguments of R, in their order, as vectors of their nonzeros; the parameters of the problem are those vectors, joined. The vectors must have the sizes of R. The options go to the problem.

SciMLBase.SDEProblem — Method
SciMLBase.SDEProblem(f::CasADiCodegen.Function, g::CasADiCodegen.Function, u0, tspan, p = SciMLBase.NullParameters();
                     jac = true, paramjac = true, sparse = false, inplace = true,
                     specialize = SciMLBase.FullSpecialize, chunk_size = nothing, split_above = nothing,
                     optlevel = nothing, cache = false, options...)

Make the SciML problem of the stochastic differential equation with the drift f and the noise g from the initial state u0 over tspan. The function of the problem is SDEFunction(f, g) with the keywords before options, which go to SciMLBase.SDEProblem.

For a noise matrix, the problem has a noise_rate_prototype of zeros of the size of g: a Matrix, with sparse = true a SparseMatrixCSC with the sparsity pattern of g, and with inplace = false an SMatrix. An option noise_rate_prototype replaces it.

Examples

using CasADiCodegen
import SciMLBase
using StochasticDiffEqLowOrder: LambaEM

x = SX.sym("x", 2)
drift = CasadiFunction("drift", [x], [-x])
G = [0.1 * x[1] 0.0 0.2; 0.0 0.3 * x[2] 0.2]       # three Wiener processes
noise = CasadiFunction("noise", [x], [G])
u0 = [1.0, 1.0]
tspan = (0.0, 1.0)
problem = SciMLBase.SDEProblem(drift, noise, u0, tspan)
solution = SciMLBase.solve(problem, LambaEM(); seed = 1)

SciMLBase.OptimizationProblem — Method
SciMLBase.OptimizationProblem(S::CasADiCodegen.Function, x0, p = Float64[]; lbx, ubx, lbg, ubg,
                              hess = true, sparse = false, lag_h = sparse && hess, chunk_size = nothing,
                              split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML problem of the solver S that CasADi's nlpsol or conic made, with generated code for the objective, the constraints and their derivatives. The keywords from hess to cache mean what they mean for OptimizationFunction.

For a conic solver, the parameters p are the nonzeros of h, then g, then the nonzeros of a, and the constraints g of the bounds are the rows of a.

The bounds have CasADi's names and default values: no bound on the unknowns, and none on the constraints. The other options go to the problem. The unknowns must be a column vector, and the vectors must have the sizes of S.

Examples

x0 = [0.0, 0.0]
problem = SciMLBase.OptimizationProblem(S, x0; lbg = [1.0], ubg = [1.0], sparse = true)
solution = SciMLBase.solve(problem, OptimizationIpopt.IpoptOptimizer())

SciMLBase.OptimizationProblem — Method
SciMLBase.OptimizationProblem(opti::casadi.Opti; hess = true, sparse = false, lag_h = sparse && hess,
                              chunk_size = nothing, split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML problem of the optimization problem that the CasADi Opti object holds, with generated code for the objective, the constraints and their derivatives.

  • The unknowns are the variables of opti, in the order of their declaration, as casadi.x(opti) joins them. Their initial values come from set_initial, or are zero.
  • The parameters are the parameters of opti (casadi.p(opti)), with the values from set_value. Each parameter must have a value.
  • The constraints are those of subject_to, with the bounds that opti gives them. opti keeps a bound on a variable as a constraint, so the problem has no lb and ub. A bound that depends on a parameter has the value of this call; a later change of the parameters in the problem does not change it.

The keywords from hess to cache mean what they mean for OptimizationFunction. The other options go to the problem. casadi.value(opti, expression, [casadi.x(opti) == DM(solution.u)]) evaluates an expression of opti at the solution.

Examples

opti = Opti()
x = variable(opti, 2)
a = parameter(opti)
minimize(opti, (x[1] - a)^2 + x[2]^2)
subject_to(opti, x[1] + x[2] >= 1)
casadi.set_value(opti, a, 0.25)
problem = SciMLBase.OptimizationProblem(opti; sparse = true)
solution = SciMLBase.solve(problem, OptimizationIpopt.IpoptOptimizer())

Make the function of a SciML problem

SciMLBase.ODEFunction — Method
SciMLBase.ODEFunction(f::CasADiCodegen.Function; jac = true, paramjac = true, sparse = false,
                      inplace = true, specialize = SciMLBase.FullSpecialize, chunk_size = nothing,
                      split_above = nothing, optlevel = nothing, cache = false, initialization = nothing,
                      solved_parameters = Symbol[], options...)

Make the SciML function of the ODE whose right side is the CasADi function f(u), f(u, p) or f(u, p, t). It holds generated code for the right side and for its Jacobians by the state (jac) and by the parameters (paramjac), which jac = false or paramjac = false leaves out.

The first result of f is the right side, a column of the size of its first argument; each further result, a column, is an observed variable. The states, the parameters, the time and the observed variables have the names of the scalar symbols and of the results of f, so a solution and a problem are indexed by name; a vector parameter is also one parameter by its own name. A function of the time without parameters takes an empty parameter argument, such as SX(0, 1). A sys among the options replaces the names. See Use the generated code with SciML packages for the naming rules.

Keywords

  • sparse = false: with true, the function has a jac_prototype, a SparseMatrixCSC with the pattern of the Jacobian, into whose stored values jac writes. It needs SparseArrays.jl loaded, jac = true and inplace = true. The Jacobians also have an out-of-place method jac(u, p, t), dense or of that pattern.
  • inplace = false: out-of-place functions that return an SVector for the right side and an SMatrix for each Jacobian, for an SVector state.
  • specialize = SciMLBase.FullSpecialize: with SciMLBase.AutoSpecialize, the solver compiled for one model serves the next (see Solver compile time for each new model).
  • initialization = nothing: a CasADi function with the arguments of f whose first result holds conditions c(u, p, t) = 0 on the initial values, which the default initializealg solves with the algebraic equations (the zero rows of mass_matrix) before the first step. The unknowns are the state, whose values are a guess, and the parameters in solved_parameters, by name or by place; see initialization_problem and Initialize differential-algebraic equations.
  • chunk_size, split_above, optlevel and cache go to build_function, the other options to SciMLBase.ODEFunction.

Throws an ArgumentError if a further result of f has no name to take (its arguments are not made of named symbols, or a name occurs twice), if sparse = true comes with jac = false or inplace = false or without SparseArrays.jl, or with inplace = false if an array has more than 1024 elements, which allows at most 32 states with jac.

Examples

using CasADiCodegen
import SciMLBase

x = SX.sym("x")
v = SX.sym("v")
k = SX.sym("k")
t = SX.sym("t")
u = vcat(x, v)
du = vcat(v, -k * x)
energy = (v^2 + k * x^2) / 2
rhs = CasadiFunction("rhs", [u, k, t], [du, energy], ["u", "k", "t"], ["du", "energy"])
f = SciMLBase.ODEFunction(rhs)
u0 = [1.0, 0.0]
tspan = (0.0, pi)
p = [4.0]
problem = SciMLBase.ODEProblem(f, u0, tspan, p)
# After `solution = solve(problem, Tsit5())`: solution[:x], solution[:energy]
source
SciMLBase.SDEFunction — Method
SciMLBase.SDEFunction(f::CasADiCodegen.Function, g::CasADiCodegen.Function; jac = true, paramjac = true,
                      sparse = false, inplace = true, specialize = SciMLBase.FullSpecialize,
                      chunk_size = nothing, split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of the stochastic differential equation du = f(u, p, t) dt + g(u, p, t) dW from the CasADi drift f and noise g. It holds generated code for the drift, the noise and the Jacobians of the drift.

f is as for ODEFunction, and the keywords mean the same as there; its further results are observed variables. g has the arguments of f and one result with a row per state:

  • a column vector gives diagonal noise, with one Wiener process per state, or scalar noise, with one Wiener process for all, when the problem has a scalar Wiener process as its option noise, such as WienerProcess(0.0, 0.0, 0.0) of DiffEqNoiseProcess.jl, whose third value starts the auxiliary process that methods of high order such as SRIW1 need;
  • a matrix gives non-diagonal noise, with one Wiener process per column. The problem needs the option noise_rate_prototype, a matrix of the size of g, which SDEProblem makes.

The noise g(out, u, p, t) writes a dense matrix or a SparseMatrixCSC of any pattern, which then takes the sparsity pattern of g. Its out-of-place method g(u, p, t) returns a new vector or matrix. With inplace = false the noise returns an SVector or an SMatrix.

Examples

using CasADiCodegen
import SciMLBase

x = SX.sym("x")
mu = SX.sym("mu")
sigma = SX.sym("sigma")
t = SX.sym("t")
q = vcat(mu, sigma)
drift = CasadiFunction("drift", [x, q, t], [mu * x])
noise = CasadiFunction("noise", [x, q, t], [sigma * x])
f = SciMLBase.SDEFunction(drift, noise)          # geometric Brownian motion

SciMLBase.DiscreteFunction — Method
SciMLBase.DiscreteFunction(f::CasADiCodegen.Function; inplace = true, specialize = SciMLBase.FullSpecialize,
                           chunk_size = nothing, split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of the map u⁺ = f(u, p, t) of a discrete-time system from the CasADi function f(u), f(u, p) or f(u, p, t). It holds generated code for the map.

The first result of f is the next state, a column vector of the size of its first argument. The solver FunctionMap of OrdinaryDiffEqFunctionMap.jl calls the map with the time of the next state, t + dt. Each further result, a column vector, is an observed variable, which a solution computes from each saved state at the time of that state. The states, the parameters, the time and the observed variables have names as for ODEFunction, and the keywords mean the same as there. With inplace = false the map returns an SVector. The other options go to SciMLBase.DiscreteFunction.

Examples

using CasADiCodegen
import SciMLBase

using OrdinaryDiffEqFunctionMap: FunctionMap

x = SX.sym("x")
r = SX.sym("r")
logistic = CasadiFunction("logistic", [x, r], [r * x * (1 - x)])
f = SciMLBase.DiscreteFunction(logistic)
u0 = [0.2]
tspan = (0.0, 50.0)
p = [3.2]
problem = SciMLBase.DiscreteProblem(f, u0, tspan, p)
solution = SciMLBase.solve(problem, FunctionMap())
solution[:x]

SciMLBase.ImplicitDiscreteFunction — Method
SciMLBase.ImplicitDiscreteFunction(f::CasADiCodegen.Function; inplace = true,
                                   specialize = SciMLBase.FullSpecialize, chunk_size = nothing,
                                   split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of the implicit map 0 = f(u⁺, u, p, t) of a discrete-time system from the CasADi function f(u⁺, u), f(u⁺, u, p) or f(u⁺, u, p, t). It holds generated code for the residual.

The first two arguments are the next and the current state, column vectors of one size. The one result, a column vector, is the residual. The solver IDSolve of ImplicitDiscreteSolve.jl solves f(u⁺, u, p, t + dt) = 0 for u⁺ at each step; its nonlinear solver differentiates the residual with dual numbers, since a SciMLBase.ImplicitDiscreteFunction holds no Jacobian. A residual of more elements than the state gives the function a resid_prototype of zeros of its size, and the step is then a least-squares problem.

By default IDSolve takes the initial state u0 of the problem as the state before the first time: it solves f(u, u0, p, t0) = 0 and starts from u. With initializealg = SciMLBase.NoInit() it starts from u0, whose algebraic elements must then satisfy their equations. IDSolve adapts its steps to the convergence of the nonlinear solver unless it receives adaptive = false and a dt.

The states have the names of the elements of u⁺, and the parameters and the time those of p and t, as for ODEFunction, whose keywords have the same meaning here. With inplace = false the residual returns an SVector; IDSolve does not take that form, since it writes the state in place. The other options go to SciMLBase.ImplicitDiscreteFunction.

SciMLBase.NonlinearFunction — Method
SciMLBase.NonlinearFunction(f::CasADiCodegen.Function; jac = true, sparse = false, inplace = true,
                            specialize = SciMLBase.FullSpecialize, chunk_size = nothing,
                            split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of the equations f(u) = 0 or f(u, p) = 0, where f is a CasADi function. It holds generated code for the residual and for its Jacobian (jac).

The first result of f is the residual, a column vector; each further result is an observed variable. A residual of another size than the first argument of f gives the function a resid_prototype of zeros of that size, for a SciMLBase.NonlinearLeastSquaresProblem. Set jac = false to leave the Jacobian out. The names, the keywords sparse, inplace, specialize and those of the code mean what they mean for ODEFunction, without the time; in place, the Jacobian also has the out-of-place method jac(u, p). The other options go to SciMLBase.NonlinearFunction.

Examples

residual = CasADiCodegen.Function("r", [z, q], [equations])
problem = SciMLBase.NonlinearProblem(SciMLBase.NonlinearFunction(residual), z0, q0)

SciMLBase.OptimizationFunction — Method
SciMLBase.OptimizationFunction(objective::CasADiCodegen.Function, constraints = nothing; hess = true,
                               sparse = false, lag_h = sparse && hess, chunk_size = nothing,
                               split_above = nothing, optlevel = nothing, cache = false, options...)

Make the SciML function of an optimization problem from the CasADi functions objective(x) or objective(x, p) and, if the problem has them, constraints with the same arguments.

The result holds generated code for the objective, its gradient (grad) and its Hessian (hess). With constraints it also holds cons, their Jacobian cons_j, and, unless lag_h, cons_h(H, x, p), where H has one matrix per constraint. hess = false leaves out the second derivatives, for a solver that uses first derivatives only; their code can take long to build.

Each of grad, hess, cons, cons_j and cons_h is in place, as hess(H, x, p), and also has the out-of-place method hess(x, p), which returns a new array. Optimization.jl calls these functions and differentiates nothing, also for a solver that needs the second derivatives.

The matrices are dense unless sparse = true. Then hess, cons_j and cons_h write the stored values of a SparseMatrixCSC with CasADi's sparsity pattern, which the result holds as hess_prototype, cons_jac_prototype and cons_hess_prototype; options must not hold a prototype then. It needs SparseArrays.jl loaded.

lag_h = true needs sparse = true and hess = true. It adds the Hessian of the Lagrange function σ f + μ' g, as lag_h(h, x, σ, μ, p), in place of cons_h: h receives the stored values of its upper triangle, whose pattern is lag_hess_prototype. Ipopt, through OptimizationIpopt.jl, then makes one call per iteration in place of one Hessian per constraint.

chunk_size, split_above, optlevel and cache go to build_function. The other options go to SciMLBase.OptimizationFunction. x must be a column vector, and the objective one number. The constraints must be a column vector.

Examples

using SparseArrays

x = SX.sym("x", 2)
objective = CasADiCodegen.Function("cost", [x], [(x[1] - 1)^2 + x[2]^2])
constraints = CasADiCodegen.Function("cons", [x], [x[1] + x[2]])
f = SciMLBase.OptimizationFunction(objective, constraints; sparse = true)
x0 = [0.0, 0.0]
problem = SciMLBase.OptimizationProblem(f, x0; lcons = [1.0], ucons = [1.0])

CasADiCodegen.Codegen.natural_continuation — Method
CasADiCodegen.natural_continuation(problem::SciMLBase.AbstractNonlinearProblem, alg, values; parameter, halvings = 3, options...) -> Vector{Pair{Float64,<:SciMLBase.NonlinearSolution}}

Solve problem with alg for each value of one parameter in values, in order, each solve starting from the solution of the one before. This is natural continuation, as for the width of a smoothed switch falling toward zero. The method exists once SciMLBase.jl is loaded.

parameter is an Integer, the place of the parameter in problem.p, a vector, or a Symbol or a String, the name of a parameter of the problem. A problem whose function is the NonlinearFunction of a CasADi function f(u, p) names each parameter after its scalar symbol in p. The first solve starts from problem.u0. options go to solve.

When a solve fails, values between the last solved one and the failed one are tried first: the geometric mean when both are positive, else the arithmetic mean, at most halvings times for each value of values. Before the first value, the value of the parameter in problem, with problem.u0, stands for the last one solved. A solve fails when its return code is not successful, or when the solve throws AssertionError (a failed check of generated code), DomainError or LinearAlgebra.SingularException; other errors propagate.

Return one pair value => solution for each value solved, intermediate ones included. The sequence stops at the first value that fails after its halvings tries. Its pair is the last one, with the return code of the solve, or ReturnCode.Failure for an error; so SciMLBase.successful_retcode(last(path).second) tells whether it reached the last value. For a path with turning points, use the extension for BifurcationKit.jl.

Throws an ArgumentError if values is empty or not finite, if halvings is negative, if a place is outside problem.p or the parameters are not a vector, if a name is unknown, or if parameter has another type.

Examples

using CasADiCodegen
using SimpleNonlinearSolve: SimpleNewtonRaphson
import SciMLBase

z = MX.sym("z")
width = MX.sym("width")
equation = z - 3 + CasADiCodegen.smooth_sign(z - 1, width)
residual = CasadiFunction("residual", [z, width], [equation])
f = SciMLBase.NonlinearFunction(residual)
problem = SciMLBase.NonlinearProblem(f, [0.0], [1.0])
widths = [0.1, 0.01, 1e-3]
path = CasADiCodegen.natural_continuation(problem, SimpleNewtonRaphson(), widths;
                                          parameter = :width)
root = last(path).second.u                                  # near [2.0]

Make a BifurcationKit problem

BifurcationKit.BifurcationProblem — Method
BifurcationKit.BifurcationProblem(f::CasADiCodegen.Function, u0, p, parameter;
                                  record_from_solution = nothing, jac = true, jet = true,
                                  chunk_size = nothing, split_above = nothing,
                                  optlevel = nothing, cache = false, options...)

Make a bifurcation problem for the steady states f(u, p) = 0 of the CasADi function f, continued in the parameter parameter. It holds generated code for the residual, its Jacobian (jac) and, with jet, the higher derivatives that BifurcationKit.jl uses.

f takes the state and the parameters, and its first result is the residual, a column vector of the size of the state. f(u, p, t) also works if the residual does not depend on t, such as the right side of an ODEFunction. States and parameters are named after the scalar symbols of f, as for SciMLBase.NonlinearFunction. Further results of f are observed variables, each named after its result.

u0, a guess of a steady state, and p, the parameter values, are vectors in the order of the symbols of f, or vectors of pairs name => value that give a value to each element. parameter is the name of a scalar parameter, such as :μ, or its place in p, from 1.

record_from_solution sets what the branch records at each point: a name, or a vector or tuple of names, of states, parameters and observed variables, recorded as a named tuple; a function (u, p; k...) -> value; or nothing for the BifurcationKit.jl default, the norm of the state.

jac = false leaves the Jacobian to automatic differentiation by BifurcationKit.jl. jet adds the Jacobian-vector product (jvp), the second and third derivatives by the state in given directions (d2F, d3F), and the derivatives by the continued parameter (R01, R11), which the normal forms at branch points and Hopf points need. With jet = false, BifurcationKit.jl computes them by automatic differentiation of the generated residual, and R11 by finite differences.

chunk_size, split_above, optlevel and cache go to build_function, and the other options to BifurcationKit.BifurcationProblem.

Examples

x, μ = SX.sym("x"), SX.sym("μ")
f = CasadiFunction("f", [x, μ], [μ * x - x^3])
u0 = [:x => 0.0]
params = [:μ => -1.0]
problem = BifurcationKit.BifurcationProblem(f, u0, params, :μ; record_from_solution = :x)
