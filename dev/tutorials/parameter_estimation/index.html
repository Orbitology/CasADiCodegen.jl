Estimate parameters through an integrator

In this tutorial, we fit the four parameters of a Lotka-Volterra model to samples of its solution by three routes: a loss whose gradient and Hessian CasADi generates through the integrator, the adjoint method of SciMLSensitivity.jl with generated Jacobians, and a Julia loss around remake that ForwardDiff.jl differentiates.

Write the model

The model of prey $x_1$ and predators $x_2$ is

\[\dot{x}_1 = (\alpha - \beta x_2)\, x_1, \qquad \dot{x}_2 = (\delta x_1 - \gamma)\, x_2.\]

An integrator takes the model as a dictionary of MX expressions (see Integrate a differential equation), with the four parameters in one vector:

using CasADiCodegen
using OrdinaryDiffEqVerner: Vern9

x, p = MX.sym("x", 2), MX.sym("p", 4)
α, β, γ, δ = p[1], p[2], p[3], p[4]
model = Dict("x" => x, "p" => p, "ode" => vcat((α - β * x[2]) * x[1], (δ * x[1] - γ) * x[2]))

Make the data

Given a vector of times, integrator returns F(x0, p), whose result holds the state at each time in one column; the solver runs once and stops at each time:

times = collect(0.0:0.1:10.0)
F = integrator("lotka_volterra", Vern9(), model, 0.0, times; abstol = 1e-10, reltol = 1e-10)
simulate = build_function(F; expression = Val{false})[1]    # the out-of-place function
X = simulate([1.0, 1.0], [1.5, 1.0, 3.0, 1.0])
size(X)
(2, 101)

The data are this solution for $(\alpha, \beta, \gamma, \delta) = (1.5, 1, 3, 1)$ with noise of standard deviation 0.01:

using Random: Xoshiro

data = X .+ 0.01 .* randn(Xoshiro(1), size(X))

Write the loss

The loss is the mean squared error of the solution for $\theta$. The data are a second argument d, so a fit to other data reuses the generated code. Calling F on symbols places the integration in the graph of the loss:

θ = MX.sym("θ", 4)
d = MX.sym("d", 2, length(times))
loss = sum(abs2, F(MX(DM([1.0, 1.0])), θ) - d) / length(data)
objective = CasadiFunction("loss", [θ, d], [loss])

gradient(loss, θ) differentiates through the integrator, by default with forward sensitivities integrated with the state. We evaluate the loss and its gradient away from the optimum:

loss_and_gradient = build_function(CasadiFunction("loss_and_gradient", [θ, d], [loss, gradient(loss, θ)]);
                                   expression = Val{false})[1]
value, ∇loss = loss_and_gradient([1.3, 0.8, 2.7, 1.1], data)
∇loss
4-element Vector{Float64}:
 -15.063707331961533
  -0.4995352016786183
  -1.8435807407894418
  -7.412808438454956

With many more parameters than states, adjoint = true in integrator integrates the adjoint equations backward instead (see How an integrator is differentiated).

Fit with a quasi-Newton method

SciMLBase.OptimizationFunction takes the unknown first and the data as the problem parameter (see Use the generated code with SciML packages). It generates the gradient and, by default, the Hessian; a quasi-Newton method needs no Hessian, so hess = false skips its compilation:

import SciMLBase

f = SciMLBase.OptimizationFunction(objective; hess = false)
problem = SciMLBase.OptimizationProblem(f, [1.2, 0.8, 2.5, 0.8], data; lb = fill(0.1, 4), ub = fill(3.0, 4))

We solve with the L-BFGS approximation of Ipopt and silence its output:

using OptimizationIpopt: IpoptOptimizer

quiet = Dict{String,Any}("print_level" => 0, "sb" => "yes")
lbfgs = IpoptOptimizer(; hessian_approximation = "limited-memory", additional_options = quiet)
solution = SciMLBase.solve(problem, lbfgs)
solution.u
4-element Vector{Float64}:
 1.5003125852831805
 1.0008340153566548
 2.9999938677426665
 0.9995317379261801

The fit is close to the true parameters $(1.5, 1, 3, 1)$, and the statistics give the number of iterations:

solution.stats.iterations
62

Fit with the exact Hessian

By default, the function also holds the Hessian, which CasADi computes from second-order sensitivities; its code takes longer to compile, but Newton steps need fewer iterations:

f_exact = SciMLBase.OptimizationFunction(objective)
problem_exact = SciMLBase.OptimizationProblem(f_exact, [1.2, 0.8, 2.5, 0.8], data; lb = fill(0.1, 4), ub = fill(3.0, 4))
solution_exact = SciMLBase.solve(problem_exact, IpoptOptimizer(; additional_options = quiet))
solution_exact.u, solution_exact.stats.iterations
([1.5003162904738536, 1.000836279278702, 2.9999827726968458, 0.9995279337540194], 25)

Compute the gradient with SciMLSensitivity

The second route integrates in Julia and generates only the right side and its Jacobians, which SciMLSensitivity.jl uses with autojacvec = false:

u, t = SX.sym("u", 2), SX.sym("t")
q = [SX.sym(name) for name in ("α", "β", "γ", "δ")]
right_side = CasadiFunction("right_side", [u, vcat(q...), t], [vcat((q[1] - q[2] * u[2]) * u[1], (q[4] * u[1] - q[3]) * u[2])])
ode = SciMLBase.ODEProblem(SciMLBase.ODEFunction(right_side; jac = true, paramjac = true), [1.0, 1.0], (0.0, 10.0),
                           [1.3, 0.8, 2.7, 1.1])

dgdu! gives the derivative of the loss by the state at sample i, and the gradient agrees with the first route to the tolerance of the solvers:

using SciMLSensitivity: adjoint_sensitivities, InterpolatingAdjoint

function dgdu!(out, u, p, t, i)
    out .= 2 .* (u .- view(data, :, i)) ./ length(data)
    return nothing
end

forward = SciMLBase.solve(ode, Vern9(); abstol = 1e-10, reltol = 1e-10)
_, ∇sciml = adjoint_sensitivities(forward, Vern9(); t = times, dgdu_discrete = dgdu!,
                                  sensealg = InterpolatingAdjoint(autojacvec = false), abstol = 1e-10, reltol = 1e-10)
maximum(abs, vec(∇sciml) - ∇loss) / maximum(abs, ∇loss)
1.910617152001251e-11

Differentiate through remake and the solver

The third route remakes ode with each trial $\theta$, which compiles nothing again, and ForwardDiff.jl differentiates through the solver and the generated right side:

import ForwardDiff

function sciml_loss(θ, (problem, data))
    solution = SciMLBase.solve(SciMLBase.remake(problem; p = θ), Vern9(); saveat = times, abstol = 1e-10, reltol = 1e-10)
    sum(abs2, Array(solution) .- data) / length(data)
end

∇forward = ForwardDiff.gradient(θ -> sciml_loss(θ, (ode, data)), [1.3, 0.8, 2.7, 1.1])
maximum(abs, ∇forward - ∇loss) / maximum(abs, ∇loss)
2.0368949453460357e-11

An implicit method also calls the generated jac, which accepts dual numbers.
