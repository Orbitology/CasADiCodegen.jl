Build large models with a loop

In this tutorial, we generate two models with a Julia loop over CasADi symbols, a chain of heat cells with a sparse Jacobian and n bodies with a dense one, and solve both.

Build a chain of heat cells

Each of N cells of a rod exchanges heat with its two neighbors and has a cubic reaction:

\[\dot{x}_i = k (N + 1)^2 (x_{i-1} - 2 x_i + x_{i+1}) - c x_i^3, \qquad i = 1, \dots, N,\]

where the left end has the temperature uin and the right end is held at zero. left and right choose the neighbor or the boundary value while the loop runs, so the graph holds only arithmetic:

using CasADiCodegen

N = 50
x = SX.sym("x", N)
k, c, uin = SX.sym("k"), SX.sym("c"), SX.sym("uin")
left(i) = i == 1 ? uin : x[i-1]
right(i) = i == N ? SX(0) : x[i+1]
equations = [k * (N + 1)^2 * (left(i) - 2x[i] + right(i)) - c * x[i]^3 for i in 1:N]

Joining three scalar parameters into one column keeps their names. The second result, the temperature y of the middle cell, is an observed variable of the solution (see Index solutions by symbol name):

heat = CasadiFunction("heat", [x, vcat(k, c, uin)], [vcat(equations...), x[N÷2]],
                      ["x", "p"], ["rhs", "y"])
casadi.n_instructions(heat)
554

The number of instructions (elementary operations of the graph) grows in proportion to N, and the generated code has no loop.

Solve the chain with a sparse Jacobian

The Jacobian is tridiagonal, and sparse = true gives the ODEFunction a jac_prototype with its pattern of 3N - 2 nonzero entries:

import SciMLBase
using SparseArrays

f = SciMLBase.ODEFunction(heat; sparse = true)
nnz(f.jac_prototype)
148

FBDF factorizes the sparse matrix:

using OrdinaryDiffEqBDF: FBDF

s = (1:N) ./ (N + 1)
x0 = sin.(pi .* s) .+ 0.5 .* sin.(3pi .* s)
tspan = (0.0, 0.1)
heat_values = [1.0, 5.0, 0.0]                             # k, c, uin
problem = SciMLBase.ODEProblem(f, x0, tspan, heat_values)
solution = SciMLBase.solve(problem, FBDF(); abstol = 1e-8, reltol = 1e-6)
solution[:y][end]
0.3248737209635141

The states are named x_0 to x_49 and the parameters k, c and uin:

heated = SciMLBase.remake(problem; p = [:uin => 1.0])
SciMLBase.solve(heated, FBDF(); abstol = 1e-8, reltol = 1e-6)[:y][end]
0.5398306146286104

A larger chain changes N only.

Build an n-body gravity model

In the second model, n bodies attract each other by gravity, with a softening $\varepsilon^2 = 0.01$; the state holds the positions, then the velocities:

\[\ddot{q}_i = \sum_{j \neq i} \frac{m_j (q_j - q_i)}{(\lVert q_j - q_i \rVert^2 + \varepsilon^2)^{3/2}}.\]

The loop computes each pair distance once, and the model also returns the total energy:

n = 5
z = SX.sym("z", 6n)
m = SX.sym("m", n)
pos(i) = z[3i-2:3i]
vel(i) = z[3n+3i-2:3n+3i]
acceleration = zeros(SX, 3n)
energy = sum(0.5 * m[i] * sum(abs2, vel(i)) for i in 1:n)
for i in 1:n, j in i+1:n
    d = pos(j) - pos(i)
    r2 = sum(abs2, d) + 0.01
    acceleration[3i-2:3i] .+= m[j] .* d ./ (r2 * sqrt(r2))
    acceleration[3j-2:3j] .-= m[i] .* d ./ (r2 * sqrt(r2))
    global energy -= m[i] * m[j] / sqrt(r2)
end
bodies = CasadiFunction("bodies", [z, m], [vcat(z[3n+1:6n], acceleration...), energy],
                        ["z", "m"], ["rhs", "energy"])

The Jacobian has a dense block of 9n² elements. The explicit method Vern7 does not call it, so jac = false leaves it out:

using OrdinaryDiffEqVerner: Vern7

g = SciMLBase.ODEFunction(bodies; jac = false, paramjac = false)
phase = 2pi .* (1:n) ./ n
positions = [[cos(a), sin(a), 0.1a] for a in phase]
velocities = [[-0.3sin(a), 0.3cos(a), 0.0] for a in phase]
z0 = vcat(positions..., velocities...)
masses = fill(1 / n, n)
orbits = SciMLBase.ODEProblem(g, z0, (0.0, 1.0), masses)
motion = SciMLBase.solve(orbits, Vern7(); abstol = 1e-10, reltol = 1e-10)
extrema(motion[:energy])
(-0.2247029630025903, -0.22470296300255588)
Compile time of the dense Jacobian for an implicit method

An implicit method on many bodies needs the dense Jacobian, whose code grows with the square of the number of states and compiles slowly; the keywords split_above, chunk_size, optlevel and cache of ODEFunction reduce that cost (see Speed up compilation of large models).
